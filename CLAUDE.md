# LOST — правила и карта

## Рабочие правила

- Пользователя зовут Стас (можно Стасон) — обращайся по имени.
- Мелкие правки делай напрямую: без plan mode, без Explore/Plan-сабагентов.
- Отвечай кратко, без пересказа того, что уже установлено.
- Модель по умолчанию — Sonnet; Opus — под сложное, широкое и под работу с документацией.
- **Комментарии и UI — по-русски.** Комментарий объясняет *почему*, а не пересказывает код.
- Открытые вопросы не живут в комментариях кода — им место в `BACKLOG.md`.

### Как читать доки

Большие файлы читаются **срезом по оглавлению**, не целиком: сперва заголовки
`grep -n '^## ' docs/ARCHITECTURE.md`, потом нужный диапазон `sed -n 'A,Bp'`.
Формулировка «прочитай файл» тянет десятки тысяч токенов. В скиллах и агентах пиши
**точную команду чтения**, а не «прочитай журнал».

## Процесс

Идея → **pm** (пишет ТЗ) → **Стас утверждает** → **design** / **seo** дополняют ТЗ →
**stage** делает → **qa** проверяет по acceptance criteria → **ship** коммитит.

Роль вызывается по имени: «pm: заведи ТЗ на …», «design: отревьюь вёрстку», «seo: аудит»,
«qa: прими 02». Роли живут в `.claude/agents/`. DEV-роль — существующий `stage`.

### Маршрутизация: кто берёт запрос

Имя роли называть не обязательно — **я определяю адресата сам по форме запроса**. Первой строкой
ответа пишу `→ <роль>: <причина одной строкой>` и **жду «да»**. Молча агента не запускаю.
Ответил «не то» — переигрываю без спора.

| Запрос выглядит так | Роль | Признак |
|---|---|---|
| «а давай сделаем…», «нужна фича», «это вообще в релиз?» | **pm** | новая идея, объём, приоритет, граница MVP |
| «сделай ТЗ 04», «продолжай по плану», «почини», «добавь поле» | **stage** | работа по коду, ТЗ уже есть |
| «криво выглядит», «что взять из Кита», «как на телефоне» | **design** | раскладка, компоненты, состояния экрана |
| «найдут ли в поиске», «ссылка разворачивается неправильно», «что закрыть от индекса» | **seo** | публичная часть, metadata, sitemap, noindex |
| «прими», «проверь, что готово», «работает?» | **qa** | сверка с acceptance criteria |
| «коммит», «залей на гит» | **ship** | закрытие сессии |

Правила разбора:

- **Вопрос, а не задача** («а можно вообще?», «как это устроено?») — отвечаю сам в чате.
  Роль — это исполнение, а не консультация.
- **Мелкая правка** (строка текста, опечатка, цвет по токену) — делаю сам, без `stage`.
  Порог: правка укладывается в один файл и не меняет поведение.
- **Запрос тянет несколько ролей** — называю цепочку и порядок: «→ pm (ТЗ) → design (раздел
  DESIGN) → stage». Запускаю по одной, не веером.
- **Форма не опознаётся** — спрашиваю, а не угадываю.
- Роль названа явно — маршрутизация не применяется, идёт названная.

- **ТЗ — один файл в `docs/tasks/`**, шаблон `docs/tasks/_TEMPLATE.md`.
  Отчёт о выполнении в ТЗ не пишется — только в `WORKLOG.md`; в ТЗ меняется строка «Статус».
- **Входит ли задача в MVP — решает только `pm`**, сверяясь с `MVP.md`, и отвечает
  «в MVP / later» с причиной.
- **Каждый чат закрывается коммитом и пушем** (скилл `ship`). Незакоммиченного между
  сессиями не остаётся: следующая сессия видит состояние в git, а не в голове.
- **Один этап — половина контекста.** Не влезает — дели на подэтапы заранее.

### Именованные процессы

Повторяющийся ход работы получает **имя** и дальше вызывается по имени. Имя — это адрес:
оно само говорит, что делать и где смотреть. Заметил, что делаем одно и то же третий раз —
предложи имя и заведи скилл в `.claude/skills/`.

Действующие: `pickup` · `stage` · `ship` · `handoff` · `serve` · `stop` · `roster-sync` · `kit`.

### Телефон ↔ компьютер

Работа идёт с двух сторон: комп (локальный Claude Code) и телефон (облачная сессия — отдельный
контейнер). **Всё, что не в git, после облачной сессии теряется.**

- Начало сессии — скилл `pickup`; конец — скилл `handoff`.
- **`web/prisma/dev.db` правит только комп.** Облачная сессия базу в коммит не берёт. Нужно
  изменить данные — `npm run db:export` → `data/snapshot.json`, накатывается на компе.
  Схема и миграции коммитятся как обычно.
- **Работаем прямо в `main`** — единственная ветка, пуш штатный. Перед сессией `git pull`.

## Где что лежит

```
/                       CLAUDE.md · MVP.md · BACKLOG.md · DECISIONS.md · WORKLOG.md
├── docs/               MAP · ARCHITECTURE · UI-GUIDELINES · DEPLOY
│   ├── tasks/          ТЗ, одно ТЗ = один файл (+ _TEMPLATE.md)
│   ├── brand/          DOCS · BRENDBOOK · COMPETITORS
│   └── archive/        закрытые планы и старые журналы
├── .claude/            агенты (роли) и скиллы
└── web/                ВСЁ приложение, работа над кодом идёт отсюда
    ├── prisma/         schema.prisma + миграции + dev.db (коммитится)
    ├── data/           roster.json, snapshot.json, theme.json — коммитятся
    ├── scripts/        ручные утилиты (tsx), не часть рантайма
    ├── public/         assets/ · templates/ · uploads/
    └── src/            app/ (роуты + API) · components/ui · lib/ · studio/
```

Подробная карта — **`docs/MAP.md`**: разделы и маршруты, ответственность каждого файла в
`src/lib/`, движок студии, скрипты ростера. **Читать перед тем, как искать файл.**

Маршруты разделены на группы: `src/app/(public)/` и `(home)/` — продукт, `(admin)/` — всё,
что пишет. На URL группы не влияют, у каждой свои layout и навигация.

Направление данных: **ростер — источник, студия и таблица — потребители.** Не хватает поля
у команды или игрока — заводи его в модели ростера, а не в payload шаблона.

## Запуск и грабли

```bash
cd web && npm run dev
```

- Порт **3000**; занят — скрипт сам поднимется на 3001+ (`web/scripts/dev-port.mjs`). Если 3000
  держит **наш же** сервер из соседнего окна, второй не поднимется (Next 16 запрещает два
  dev-сервера в одной папке) — скрипт печатает адрес живого. Погасить всё — скилл `stop`.
- Проверка связки с БД: `GET /api/health` → `{ ok, teams, matches, points }`.
- Проверять UI только через `localhost`: на `127.0.0.1` Next 16 блокирует dev-ресурсы, гидрация
  не проходит и не работает ни одна кнопка.
- `web/.env` (в `.gitignore`, шаблон — `web/.env.example`): `DATABASE_URL`, `OPENAI_API_KEY`,
  `STEAM_API_KEY`, `GOOGLE_CLIENT_ID/SECRET`, `OWNER_EMAIL`, `FRAME_ANCESTORS`, `AUTH_SECRET`,
  `TG_BOT_TOKEN`, `TG_CHAT_ID`. Без `OPENAI_API_KEY` не работает `/studio/generate`; вход есть при
  `GOOGLE_CLIENT_*` или просто с `AUTH_SECRET`; без `OWNER_EMAIL` некому раздавать права.
  Почтовых ключей нет — писем приложение не шлёт. Новая машина с нуля — `web/README.md`.
  **Ключи только в `.env`** — ни в коде, ни в коммитах, ни в чат.
- Проверка: `npx tsc --noEmit`, `npm run lint`. Тестов в проекте нет.
  **Перед коммитом этапа — ещё и `npm run build`:** dev собирает маршрут за маршрутом, а прод —
  весь граф разом, и часть ошибок видит только он (клиентские хуки в файле, который импортируют
  серверные компоненты — ровно такой случай, см. `pouf/password-field.tsx`).
  После переноса файлов между папками `.next/types/validator.ts` врёт устаревшими путями —
  лечится `rm -rf .next/types`.

**Prisma 7:**
- `new PrismaClient()` без аргумента **не компилится** — нужен driver-adapter,
  используем `@prisma/adapter-libsql`. Клиента не создавать: `src/lib/prisma.ts` — singleton.
- Клиент генерится в `src/generated/prisma`, импорт — `@/generated/prisma/client`.
- `DATABASE_URL` в `web/.env`, путь **относительный** к `web/` — абсолютный `file:`-URL ломает
  libsql на Windows.
- sqlite не умеет enum → строковые поля с комментарием-перечислением в схеме.
- Правил схему — `npx prisma generate`, иначе типы разъедутся.

**Next.js 16 (Turbopack):** версия новее того, что агент «помнит». Перед написанием кода с
непривычным API — читать `web/node_modules/next/dist/docs/`, а не полагаться на память.
Продублировано в `web/AGENTS.md`.

## Конвенции

- Слаг (`slug`) — ключ импорта **и** имя файла ассета. Одно имя связывает таблицу, БД и картинку:
  `uploads.ts` подставит `<slug>-logo.png` там, где поле пустое.
- Скрипты в `scripts/` идемпотентны и запускаются руками; в рантайм-код их не тянуть.
  Читалка xlsx общая — `scripts/xlsx.ts` (ради гиперссылок ячеек: в CSV их нет).
- `public/uploads/` — ассеты релиза, коммитятся вместе с кодом. Исключения — `uploads/generated/`
  и `uploads/postgame/`: это вывод, а не ассеты, обе в `.gitignore`.
- **`prisma/dev.db` коммитится.** Сетка встреч и результаты вводятся руками в UI, скриптами их не
  восстановить. Бинарник не мержится: работаем на одной машине за раз, `git pull` перед началом.
  Решение пересматривается в `docs/tasks/01-vps-i-baza.md`.
- Стили — Tailwind v4, светлая тема Light Clay, компоненты только из Кита (`components/pouf/`).
  Новый компонент заводится в Ките, а не по месту.

**Правило:** новая подсистема → абзац в `docs/ARCHITECTURE.md`; принятое решение → блок в
`DECISIONS.md`; где лежит → строка в `docs/MAP.md`; что осталось → строка в `BACKLOG.md`;
что делаем → ТЗ в `docs/tasks/`.
