# DEPLOY-MANUAL — развернуть руками, шаг за шагом

Пошаговый прогон для человека за клавиатурой: от пустого VPS до работающего `https://`.
Скилл `serve` делает то же самое, но локально и через временный туннель — разница описана
в §8. Почему именно так устроено (образ, тома, прокси) — `docs/DEPLOY.md`; здесь только
порядок действий и точные команды.

**Что должно получиться:** приложение живёт в контейнере на `127.0.0.1:3001`, наружу его
выводит Caddy с сертификатом Let's Encrypt, база и картинки лежат на томах и переживают
выкладку.

---

## 0. Что нужно до начала

| | Требование | Почему |
|---|---|---|
| Площадка | VPS с Ubuntu/Debian, 2 ГБ RAM, **постоянный диск** | Next 16 — долгоживущий Node-процесс, а не папка со статикой. Serverless не годится: база и картинки эфемерные. PHP-хостинг не годится в принципе |
| Домен | запись `A` на IP сервера | без него не будет сертификата, а бот будет звать людей по адресу, куда они не попадут |
| Доступ | `root` или `sudo`, ssh-ключ | |

## 3. `.env`

Файл в `.gitignore`, на сервере заводится руками:

```bash
cp .env.example .env && nano .env
```

Минимум, без которого сезон не открыть:

| Переменная | Что писать | Что сломается без неё |
|---|---|---|
| `BASE_URL` | `https://<ваш домен>` | канонические адреса, `sitemap.xml`, OG-превью и ссылки бота уедут на localhost |
| `OWNER_EMAIL` | почта владельца лиги, **та же, под которой вы входите** | некому раздавать права: владелец получит роль `player` и увидит «прав нет» |
| `AUTH_SECRET` | длинная случайная строка, сгенерировать: `openssl rand -hex 32` | при входе по почте и паролю сессия не подписывается — вход «не залипает» |

Остальное — по мере надобности, приложение работает и без них:

| Переменная | Что даёт |
|---|---|
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | кнопку «Войти через Google». В Google Cloud Console в Authorized redirect URIs добавить `https://<домен>/api/auth/google/callback` |
| `TG_BOT_TOKEN` | телеграм-бота: квиз заявки команды, привязку профиля, вход по коду, доставку ссылки сброса пароля |
| `TG_CHAT_ID` | куда слать инфографику матча и дайджест |
| `STEAM_API_KEY` | кнопку «Из Steam» — запасной источник матча, когда лежит OpenDota. Ключ бесплатный |
| `OPENAI_API_KEY` | генерацию картинок в `/studio/generate` |
| `FRAME_ANCESTORS` | право встроить нас в `<iframe>` на домене основного сайта |
| `LOBBY_STAND` | `1` — в комнате лобби появляется «Заполнить стенд»: нажавший становится капитаном стороны A, остальные места занимают боты и ходят сами (ТЗ 42ж). Работает и здесь, на прод-сборке, но только у аккаунта с правом `tools`. Прогон закончен — убрать строку и `docker compose up -d` |

Чего в `.env` быть **не должно**: `ADMIN_PASSWORD` (пароль-админки убран, доступ даёт роль) и
`DEV_LOGIN_EMAIL` (на проде игнорируется, но держать его там незачем). `DATABASE_URL` не
трогать — в контейнере он переопределяется на `file:./data/dev.db`.

## 4. Первый запуск

```bash
docker compose up -d --build
```

Сборка занимает несколько минут. Что произойдёт на старте контейнера (`docker-entrypoint.sh`):
создадутся тома, база из репозитория скопируется в том **только если её там ещё нет**,
лого и фото доложатся из образа, накатятся миграции `prisma migrate deploy`.

Проверить:

```bash
curl http://127.0.0.1:3001/api/health
```

Ответ вида `{"ok":true,"teams":49,"matches":212,"points":100}` означает, что связка с базой
поднялась. Молчание или ошибка — смотреть `docker compose logs -f web`.

## 5. Домен и HTTPS

Контейнер намеренно слушает только `127.0.0.1:3001`. Открыть его на `0.0.0.0` — значит
выставить служебную часть в интернет по голому http.

```bash
apt install -y caddy
```

`/etc/caddy/Caddyfile`:

```
app.leagueofspirits.ru {
    reverse_proxy 127.0.0.1:3001
}
```

```bash
systemctl reload caddy
```

Caddy сам получит сертификат Let's Encrypt — при условии, что запись `A` в DNS уже смотрит на
IP сервера и порты 80/443 открыты.

После того как домен заработал:

1. вписать его в `BASE_URL` и перезапустить: `docker compose up -d`;
2. добавить `https://<домен>/api/auth/google/callback` в Google Cloud Console;
3. привязать домен к боту в BotFather (`/setdomain`) — это включает Telegram Login Widget
   **вторым** способом входа, не вместо кода: код работает и без домена.

## 6. Бот — отдельный процесс

Бот в контейнер не входит: это долгоживущий процесс с long polling, публичный адрес ему не
нужен. Поднимать на той же машине:

```bash
cd lost-league/web && npm ci && npm run bot
```

Чтобы пережил закрытие ssh — под systemd или `npm run bot:up` (лог: `npm run bot:log`,
остановить: `npm run bot:down`).

## 7. Обновление после правок

```bash
cd lost-league && git pull && cd web && docker compose up -d --build
```

Пересборка обязательна: образ — снимок кода на момент прошлой сборки, без `--build` контейнер
будет отдавать старое. Данные при этом не трогаются — они на томах.

## 8. То же самое локально (что делает `serve`)

Скилл `serve` — это те же два шага, которые можно выполнить руками:

```bash
cd web && docker compose up -d --build
```

```bash
cloudflared tunnel --url http://localhost:3001 --no-autoupdate
```

Вторая команда печатает случайный адрес `https://<...>.trycloudflare.com` — это и есть
публичная ссылка. Отличия от сервера, важные на практике:

- **адрес меняется** при каждом перезапуске туннеля — природа quick tunnel, не баг;
- ссылка жива, пока включён Mac, живой контейнер и процесс `cloudflared`;
- на сервере туннель не нужен: там прямой порт за Caddy;
- сертификат на сервере свой, у туннеля — Cloudflare.

**Стенд лобби на контейнере.** Кнопка «Заполнить стенд» включается той же строкой `LOBBY_STAND=1`
в `web/.env` — контейнер читает этот файл целиком (`env_file` в `docker-compose.yml`), и после
правки достаточно `docker compose up -d` (перезапуск, пересборка не нужна). Аккаунты стенда
(`stand-*@lost.test`) кнопка заводит сама: база контейнера живёт на томе и стенда может не
содержать. `/dev/as/<id>` на контейнере не работает и не должен — это прод-сборка.

Скрипт `.claude/skills/serve/serve.sh` дополнительно ставит `cloudflared`, ждёт `/api/health` и
кладёт pid, лог и адрес в `web/.cache/`. Снять туннель, оставив контейнер: `stop.sh` или
`pkill -f cloudflared`.

## 9. Бэкап и восстановление

Всё состояние приложения — два тома:

| Том | Что внутри | Восстановимо? |
|---|---|---|
| `lost-data` | база лиги: составы, сетка встреч, результаты | **нет** — вводится руками в UI |
| `lost-uploads` | лого и фото ростера, архив постгеймов | частично, лого — скриптами импорта |

Снять бэкап:

```bash
docker compose exec -T web cat /app/data/dev.db > backup-$(date +%F).db
```

Положить обратно:

```bash
docker compose cp backup-2026-09-17.db web:/app/data/dev.db && docker compose restart web
```

Делать по расписанию — `cron` раз в сутки, копию уносить с машины.

**Главное про базу.** `web/prisma/dev.db` из репозитория копируется в том **только при первом
запуске**. Дальше боевая база живёт своей жизнью, и `git pull` её не затирает — иначе каждая
выкладка стирала бы результаты матчей. Обратная сторона: с этого момента база на сервере и
база в репозитории расходятся, и надо решить, кто главный. Правите через сайт — главный
сервер, локальную базу считайте тестовой. Это ровно тот вопрос, который ждёт письменного
ответа в ТЗ 01.

## 10. Когда что-то не так

```bash
docker compose logs -f web      # логи приложения
docker compose ps               # статус и healthcheck
docker compose exec web sh      # заглянуть внутрь
```

| Симптом | Причина |
|---|---|
| 502 от Caddy | контейнер не поднялся — `docker compose logs web` |
| Сертификат не выдан | DNS ещё не смотрит на сервер или закрыт 80/443 |
| Владелец видит «прав нет» | `OWNER_EMAIL` не совпадает с почтой, под которой вошли |
| Вход «не залипает» | пуст `AUTH_SECRET` при входе по паролю |
| Бот зовёт на localhost | пуст `BASE_URL` |
| Превью ссылки без картинки | `BASE_URL` не на https-домене |
| Пропали лого команд | том `lost-uploads` пересоздан — докладываются из образа при старте |
| Матч не грузится из OpenDota | сторонний сервис лежит, пробовать «Из Steam» (нужен `STEAM_API_KEY`) |
