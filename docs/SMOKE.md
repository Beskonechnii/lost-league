# SMOKE — прогон перед выкладкой

Один и тот же список проверок по продукту целиком. Гоняется **перед каждой выкладкой**, а не
сочиняется заново. Исполнитель — роль `qa`. Чек-лист нового раздела (`UI-GUIDELINES.md` §8) он не
заменяет: тот про один раздел, этот — про весь сезон.

Вердикт по пункту — ровно один из трёх: **pass** · **fail** · **не проверено** (с причиной).
Придуманный pass хуже честной дыры: на этот список смотрят при открытии сезона.
Найденный дефект **не чинится внутри прогона** — он идёт строкой в `BACKLOG.md` или отдельным ТЗ.

## Где гонять

| Среда | Чем поднимается | Что на ней проверяется |
|---|---|---|
| Боевой адрес | выкладка по `docs/DEPLOY.md` | **всё**; это единственный полноценный прогон |
| Локальная прод-сборка | `npm run build` → `npx next start -p 4203` | гость, права, ширины, SEO — всё, кроме внешних служб |
| Локальный dev | `npm run dev` (порт 3000) | только зрячие правки по ходу работы |

**Грабли, без которых прогон врёт:**

- **`DEV_LOGIN_EMAIL` делает гостя владельцем.** Дев-сервер с этой переменной пускает запрос без
  куки в `/admin` — проверять на нём права **нельзя**. Признак: `curl -s -D- -o /dev/null
  localhost:3000/me` отдаёт редирект на чей-то профиль вместо страницы входа. Гость и роли
  проверяются на прод-сборке (`next start`) или на боевом: там переменная не действует.
- Только `localhost`, не `127.0.0.1`: Next 16 блокирует dev-ресурсы для хоста не из
  `allowedDevOrigins`, гидрация не проходит и не работает ни одна кнопка.
- Порт 3000 часто занят сервером Стаса — свой поднимать на 4203.
- Заводил записи под проверку — снеси их и скажи в отчёте, что заводил и что снёс.
  `web/prisma/dev.db` — живая база лиги.

## Гость

- [ ] Главная открывается, блоки не пустые, «Войти» на месте
- [ ] Турнир → дивизион → таблица → встреча → отчёт матча проходятся ссылками без тупика
- [ ] Профиль игрока и страница команды открываются, медаль ранга и составы на месте
- [ ] `/roster` в обоих разрезах (команды и игроки), поиск по лиге что-то находит
- [ ] Лента `/series` листается, подпись карточки называет турнир, встречи больше чем одного турнира
- [ ] Битый адрес даёт наш 404 («Такой страницы нет»), а не системную страницу Next.
      Проверять и слаг (`/tournaments/<нет>`, `/players/<нет>`), и id (`/roster/teams/999999`)
- [ ] Служебное гостю не отдаётся: `/admin`, `/admin/<группа>`, `/studio`, `/match`, `/underbeer`
      уводят на `/me?next=…`, а не показывают пустой экран с данными в разметке

## Новый игрок

- [ ] Регистрация по почте и паролю; слабый пароль отвергается внятным текстом
      («Пароль должен быть не короче 10 символов»), аккаунт при этом не заводится
- [ ] Анкета проходится целиком; уход со страницы на середине не теряет ответы
- [ ] Привязка Steam и привязка телеграма проходят и отражаются в профиле
- [ ] После отправки виден welcome, а не тупик
- [ ] Сброс пароля: письмо-ссылка уходит в телеграм, ссылка одноразовая, истёкшая даёт экран отказа,
      ответ формы одинаков для любой почты
- [ ] Смена пароля гасит прежние сессии: старая кука после неё в дверь не пускает

## Капитан

- [ ] Заявка команды в турнир собирается из пула и отправляется
- [ ] Игроки состава получают запрос согласия и могут ответить
- [ ] Заказ встречи через бота доходит до соперника и до организатора
- [ ] Дивизион заполнен: в публичной заявке «мест нет», дивизион не выбирается

## Оператор

- [ ] Апрув заявки заводит команду, игроков и состав
- [ ] Правка счёта встречи отражается в таблице дивизиона
- [ ] Импорт составов проходит на `--dry` без ошибок: `npx tsx scripts/import-roster.ts --dry`
- [ ] Импорт CRM проходит на `--dry` без ошибок: `npx tsx scripts/import-crm.ts --file <выгрузка> --dry`
- [ ] После записи импорта — возврат на турнир, команды видны в участниках
- [ ] Бейдж очереди на хабе `/admin` равен числу на `/admin/moderation` при **непустой** очереди
- [ ] Лимит команд у дивизиона сохраняется, даёт «8 из 12» у дивизиона и сумму у турнира,
      растёт после апрува; апрув и ручное добавление сверх лимита просят подтверждения
- [ ] Группировка по серии: LOST первой группой, «Прочие турниры» последними,
      «LOST Cup» и «lost cup» — одна группа, стёртая серия не теряет турнир
- [ ] Черновик турнира не виден ни в сериях, ни в хронологии — ни гостю, ни игроку
- [ ] Баннер главной: правка в `/admin/banner` видна на главной; выключенный баннер отдаёт
      герой по данным, а не пустой первый экран
- [ ] Уведомление оператору приходит на событие (новая анкета, привязка профиля)

## Права — главное

Проверяется **на прод-сборке или на боевом**: на dev с `DEV_LOGIN_EMAIL` эти пункты бессмысленны.
Учётки под проверку заводятся временно и сносятся после.

- [ ] Чужой профиль не редактируется — ни формой, ни прямым POST
      (адресата правки в форме нет: `saveProfile` берёт игрока из сессии)
- [ ] Чужая беседа не открывается по прямой ссылке и по API:
      `GET /api/chat/messages?conversationId=<чужой>` → 403 «Это не ваша беседа»
- [ ] Админ **без** конкретного права получает отказ и на странице (текст «Раздел открывает
      право …»), **и** в запросе на запись (403 с тем же правом в тексте)
- [ ] Админ **с одним правом** видит на `/admin` только свою группу инструментов — трёх остальных
      заголовков нет; страница чужой группы объясняет, каким правом она открывается
- [ ] Игрок без инструментов не видит пункт «Админ» в шапке, `/admin` уводит на `/me`
- [ ] Гость на `/admin/*` не видит данных и получает отказ, а не пустой экран
- [ ] Куки удалённого аккаунта недостаточно, чтобы что-то сделать: шапка становится гостевой,
      запись отбивается 401/403

## SEO

- [ ] `robots.txt` отдаётся, служебное закрыто (`/admin/`, `/api/`, `/chat/`, `/me/`, `/login/`,
      `/studio/`, `/match`, `/lobby/`, `/overlay/`, `/underbeer/`)
- [ ] `sitemap.xml` отдаётся, адреса в нём — **боевого домена**, а не localhost
- [ ] `noindex` на `/me`, `/chat`, `/login/*`, во всей служебной части
- [ ] У турнира, дивизиона, игрока и команды свои `title`, `description` и `og:*`
- [ ] Превью ссылки в телеграме разворачивается картинкой и заголовком (только на боевом:
      телеграм не ходит в localhost)

## Техника

- [ ] Из `web/`: `npx tsc --noEmit`, `npm run lint`, `npm run build` — чисто
- [ ] **390px**: ни одна страница продукта не скроллится горизонтально
- [ ] **1280px**: у **вошедшего оператора** (у него в баре лишний пункт «Админ») ряд разделов стоит
      одной строкой — без переноса, второго ряда и горизонтальной прокрутки
- [ ] **1440px**: колонки не разъезжаются, максимальные ширины по токенам
- [ ] В консоли браузера нет своих ошибок на ключевых экранах
- [ ] Перезапуск сервера не теряет данных (`/api/health` до и после совпадает)

Переполнение меряется, а не смотрится:
`document.documentElement.scrollWidth - document.documentElement.clientWidth` — должен быть `0`.
Строку бара считать так же: у всех ссылок шапки одинаковый `getBoundingClientRect().top`.
