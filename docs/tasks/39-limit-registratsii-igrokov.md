# ТЗ 39: Лимит записи на индивидуальный турнир — оператор задаёт число мест

**Статус:** done · принято 24.09.2026
**Входит в MVP:** нет — Mix Cup и UNDERBEER целиком later (`MVP.md`)

Заголовок обобщён с «Mix Cup» на «индивидуальный турнир»: по ответу Стаса 23.09.2026 UNDERBEER
тоже становится форматом с публичной регистрацией (`docs/tasks/37-*.md`, Scope п.4) — лимит нужен
обоим одинаково, одним механизмом.

## Цель

Вводная Стаса 23.09.2026 — «открываем регистрацию для определённого числа команд/игроков» —
отменяет прежнее решение «лимита участников нет» (`docs/tasks/34-mix-cup-registratsiya.md`, «НЕ
входит», подтверждено `DECISIONS.md`/`BACKLOG.md` 22.09.2026 в развилках Mix Cup). Оператор
должен мочь ограничить приём числом мест на индивидуальную (игроковую) регистрацию — так же, как
уже ограничивает число команд в дивизионе. Верно для Mix Cup и для UNDERBEER-турнира одним кодом.

Закрыто, когда: оператор указывает лимит у турнира индивидуального формата, форма записи отказывает
гостю текстом после того, как места кончились, а отмена записи освобождает место следующему.

## Контекст

- **Лимит команд уже есть и уже работает** — `Division.teamLimit` (`web/prisma/schema.prisma:68`),
  проверяется в `web/src/lib/tournaments.ts` и на приёме заявок
  (`web/src/app/(public)/tournaments/[slug]/apply/page.tsx`,
  `web/src/app/(admin)/admin/tournaments/actions.ts`). **Этот механизм не трогаем** — задача
  только про индивидуальную регистрацию, у которой лимита нет вообще, потому что дивизионов и
  команд там нет.
  Данные лимита пока пустые у всех дивизионов (`docs/MANUAL-TASKS.md` §5) — это не блокирует
  проверку команд, просто пока непроверенный путь; вне рамки этого ТЗ.
- Индивидуальная регистрация: `web/src/lib/mixcup.ts` (после ТЗ 37 — обобщается на оба формата,
  возможно переезжает/переименовывается, точное имя решает `stage`), модель
  `TournamentRegistration` (после ТЗ 37 — `tournamentId`). Сегодня без ограничений: `upsert` без
  проверки числа записей.
- Форма ошибок уже умеет отвечать текстом, не молчать (`docs/tasks/30-formy-govoryat-chto-ne-tak.md`,
  принято) — новый отказ пользуется тем же механизмом.
- Размеченный тип результата записи (`MixCupJoinResult` в `mixcup.ts` сегодня) — `ok: false` с
  `reason: "closed" | "no-profile"`. Новая причина добавляется в этот же тип, а не отдельным флагом.

## Scope

**Входит:**

1. **`Tournament.registrationLimit Int?`** — общее поле (осмысленно для `kind: "mixcup"` и `kind:
   "underbeer"`; у сезонных турниров лимит живёт по-прежнему на дивизионе). Пусто — приём
   неограничен, как сегодня.
2. **Проверка при записи** — для обоих индивидуальных форматов одним кодом: функция записи
   считает число существующих `TournamentRegistration` турнира; при лимите и его достижении —
   отказ `reason: "full"`, новая запись не создаётся. Форма показывает текст отказа тем же
   механизмом, что и «приём закрыт».
3. **Отмена освобождает место.** Функция отмены не меняется по коду, но по факту (строка удаляется)
   следующая запись снова возможна — никакого списка ожидания заводить не нужно, это и так следует
   из простого подсчёта строк.
4. **Оператор видит и задаёт лимит** на операторской консоли турнира (для Mix Cup — `/admin/mixcup/
   <id>`, `rules-panel.tsx`, тот же экран, где тумблеры «Украсть»/«Закрепить»; для UNDERBEER-
   турнира — его консоль из ТЗ 37) и видит счётчик «Записано X из N» там же и/или в списке
   участников.
5. **Публичная форма записи показывает остаток мест** (Mix Cup и UNDERBEER-турнир — одним видом),
   если лимит задан (сколько именно — доверяем `design`: число, полоска, просто «мест нет» при
   нуле — решает `design`).

**НЕ входит:**

- **Лист ожидания.** Не просили — «определённого числа», не «а дальше очередь». Решение Стаса
  22.09.2026 «листа ожидания нет» (ТЗ 34, «НЕ входит») в этой части не отменяется, отменяется
  только «лимита нет».
- **Автозакрытие приёма по достижении лимита** (флип `Tournament.status`). Приём по-прежнему
  закрывает оператор — лимит блокирует НОВЫЕ записи, но не меняет статус турнира сам. Тот же
  принцип, что уже был закрыт 22.09.2026 для этой части.
- **Лимит для сезонных турниров (`Division.teamLimit`)** — уже есть, не трогаем, см. Контекст.
- **Валидация «лимит меньше уже записанных»** при уменьшении оператором задним числом — на
  приёмке решается простым правилом «не даём поставить меньше текущего числа записей», без UI
  вокруг этого; если `design`/`qa` найдут это недостаточным, возвращается строкой в `BACKLOG.md`.

## Требования · DEV

- Миграция Prisma: `Tournament.registrationLimit Int?`.
- Тип результата записи: `reason` получает значение `"full"`.
- Функция записи: подсчёт `prisma.tournamentRegistration.count({ where: { tournamentId } })` перед
  созданием новой записи; сравнение с `registrationLimit` (пусто — не ограничивать). Одна функция
  на оба формата — не дублировать под UNDERBEER.
- Операторские консоли (Mix Cup и UNDERBEER-турнира) — поле ввода лимита, сохраняется тем же
  путём, что и тумблеры.
- Публичные формы записи (Mix Cup и UNDERBEER-турнира) — читают остаток мест, показывают текст
  отказа при `reason: "full"`.

## Требования · DESIGN

Заполняет `design`: как показан остаток мест на форме записи (число / полоска / оба состояния —
есть места / мест нет), вид счётчика в операторской панели. Один вид на оба формата.

## Acceptance criteria

- [ ] Оператор задаёт лимит 2 у турнира индивидуального формата без записей → форма записи доступна

- [ ] Оператор видит на консоли турнира счётчик «записано X из N»
