# ТЗ 39: Лимит записи на Mix Cup — оператор задаёт число мест

**Статус:** draft · зависит от `docs/tasks/37-turnir-format.md` (нужен `Tournament.kind`),
`stage` не стартует раньше него
**Входит в MVP:** нет — Mix Cup целиком later (`MVP.md`)

## Цель

Вводная Стаса 23.09.2026 — «открываем регистрацию для определённого числа команд/игроков» —
отменяет прежнее решение «лимита участников нет» (`docs/tasks/34-mix-cup-registratsiya.md`, «НЕ
входит», подтверждено `DECISIONS.md`/`BACKLOG.md` 22.09.2026 в развилках Mix Cup). Оператор
должен мочь ограничить приём числом мест на индивидуальную (игроковую) регистрацию — так же, как
уже ограничивает число команд в дивизионе.

Закрыто, когда: оператор указывает лимит у mixcup-турнира, форма записи отказывает гостю текстом
после того, как места кончились, а отмена записи освобождает место следующему.

## Контекст

- **Лимит команд уже есть и уже работает** — `Division.teamLimit` (`web/prisma/schema.prisma:68`),
  проверяется в `web/src/lib/tournaments.ts` и на приёме заявок
  (`web/src/app/(public)/tournaments/[slug]/apply/page.tsx`,
  `web/src/app/(admin)/admin/tournaments/actions.ts`). **Этот механизм не трогаем** — задача
  только про индивидуальную регистрацию, у которой лимита нет вообще, потому что дивизионов и
  команд там нет.
  Данные лимита пока пустые у всех дивизионов (`docs/MANUAL-TASKS.md` §5) — это не блокирует
  проверку команд, просто пока непроверенный путь; вне рамки этого ТЗ.
- Индивидуальная регистрация: `web/src/lib/mixcup.ts` → `registerForMixCup()`, модель
  `MixCupRegistration` (после ТЗ 37 — `tournamentId`). Сегодня без ограничений: `upsert` без
  проверки числа записей.
- Форма ошибок уже умеет отвечать текстом, не молчать (`docs/tasks/30-formy-govoryat-chto-ne-tak.md`,
  принято) — новый отказ пользуется тем же механизмом.
- `MixCupJoinResult` (`mixcup.ts`) — размеченный тип результата записи, `ok: false` с `reason:
  "closed" | "no-profile"`. Новая причина добавляется в этот же тип, а не отдельным флагом.

## Scope

**Входит:**

1. **`Tournament.registrationLimit Int?`** — общее поле (не только для `kind: "mixcup"`, но
   осмысленно сейчас только для него; у сезонных турниров лимит живёт по-прежнему на дивизионе).
   Пусто — приём неограничен, как сегодня.
2. **Проверка при записи.** `registerForMixCup()` считает число существующих
   `MixCupRegistration` турнира; при лимите и его достижении — отказ `reason: "full"`, новая
   запись не создаётся. Форма показывает текст отказа тем же механизмом, что и «приём закрыт».
3. **Отмена освобождает место.** `unregisterFromMixCup()` не меняется по коду, но по факту (строка
   удаляется) следующая запись снова возможна — никакого списка ожидания заводить не нужно, это
   и так следует из простого подсчёта строк.
4. **Оператор видит и задаёт лимит** на экране настроек mixcup-турнира (`/admin/mixcup/<id>`,
   `rules-panel.tsx` — тот же экран, где тумблеры «Украсть»/«Закрепить») и видит счётчик «Записано
   X из N» там же и/или в списке участников (`participants-panel.tsx`).
5. **Публичная форма записи показывает остаток мест**, если лимит задан (сколько именно —
   доверяем `design`: число, полоска, просто «мест нет» при нуле — решает `design`).

**НЕ входит:**

- **Лист ожидания.** Не просили — «определённого числа», не «а дальше очередь». Решение Стаса
  22.09.2026 «листа ожидания нет» (ТЗ 34, «НЕ входит») в этой части не отменяется, отменяется
  только «лимита нет».
- **Автозакрытие приёма по достижении лимита** (флип `Tournament.status`). Приём по-прежнему
  закрывает оператор — лимит блокирует НОВЫЕ записи, но не меняет статус турнира сам. Тот же
  принцип, что уже был закрыт 22.09.2026 для этой части.
- **Лимит для сезонных турниров (`Division.teamLimit`)** — уже есть, не трогаем, см. Контекст.
- **Валидация «лимит меньше уже записанных»** при уменьшении оператором задним числом — на
  приёмке решается простым правилом «не даём поставить меньше текущего числа записей», без UI
  вокруг этого; если `design`/`qa` найдут это недостаточным, возвращается строкой в `BACKLOG.md`.

## Требования · DEV

- Миграция Prisma: `Tournament.registrationLimit Int?`.
- `MixCupJoinResult`: `reason` получает значение `"full"`.
- `registerForMixCup()`: подсчёт `prisma.mixCupRegistration.count({ where: { tournamentId } })`
  перед созданием новой записи; сравнение с `registrationLimit` (пусто — не ограничивать).
- Экран настроек (`rules-panel.tsx`) — поле ввода лимита, сохраняется тем же путём, что и
  тумблеры.
- Публичная форма (`mixcup/[slug]/page.tsx`, `actions.ts`) — читает остаток мест, показывает текст
  отказа при `reason: "full"`.

## Требования · DESIGN

Заполняет `design`: как показан остаток мест на форме записи (число / полоска / оба состояния —
есть места / мест нет), вид счётчика в операторской панели.
