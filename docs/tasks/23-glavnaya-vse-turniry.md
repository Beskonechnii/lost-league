# ТЗ 23: Главная показывает все турниры, а не по одному на статус

**Статус:** ready
**Входит в MVP:** да

## Цель

Капитан второй команды, набор в турнир которой открыт прямо сейчас, находит свой турнир с главной
и доходит до формы заявки. Сегодня витрина держит ровно один турнир на статус, и при двух открытых
наборах второй не виден на главной вовсе и не собирает заявки. Закрыто, когда с `/` видны оба
открытых набора и из каждого есть путь в его форму.

## Scope

**Допущение по листалке (названо явно, а не подразумевается).** Стрелки листают **карточки внутри
секции статуса**. Три секции (идёт · приём заявок · завершён) остаются на экране разом и стрелками
не листаются: их всего три, они видны одновременно уже сейчас, и прятать их за стрелку — терять
соседей ради экономии, которой нет. Листается то, чего может быть много, — турниры одного статуса.

**Входит:**
- Секция статуса на главной показывает **все** турниры своего статуса, а не первый.
- Внутри секции — листание стрелками вперёд/назад, когда турниров больше, чем помещается.
- Сборный `/apply`: при нескольких открытых наборах человек **выбирает турнир**, а не попадает
  в угаданный. При одном открытом поведение прежнее — редирект в форму.
- Экран ожидания `/me` (welcome): зовёт заявиться так, чтобы открытые наборы не терялись.
- Пустая секция по-прежнему показывает лунку (`EMPTY_SLOT`).

**НЕ входит:**
- Редактор баннера главной — отдельная работа, `docs/tasks/25-redaktiruemyi-banner.md`.
- Переделка баннера под несколько наборов — карточка секции уже даёт вход в каждый турнир,
  второй призыв на том же экране только спорит с первым.
- Фильтры и пагинация полного списка турниров — для этого есть `/tournaments` (ТЗ 09).
- Черновики на витрине — решение прежнее: турнир становится событием лиги, когда открыт на заявки.

## Требования · DEV

- «Какие турниры открыты на приём» — **одно место правды** в `lib/tournaments.ts`. Существующая
  `openForRegistration()` остаётся для случаев, где нужен ровно один, и выражается через общий
  список, а не через вторую копию правила `registrationOpen`.
- Порядок карточек внутри секции — тот же, что в источнике (`listTournaments` сортирует по старту
  вниз); своей сортировки секция не заводит.
- Серверный рендер главной сохраняется: листалка — поведение клиента поверх уже отданного списка,
  догрузки по стрелке нет.

## Требования · DESIGN

Заполняет роль `design`: вид стрелок и их место у секции, поведение на 390px (сейчас карточки
листаются свайпом — стрелки не должны его отменять), состояние «турнир один» (стрелки скрыты либо
неактивны — выбрать и назвать), выбор турнира на `/apply`.

## Требования · SEO

служебным перенаправлением и в `sitemap` не добавляется. Отдельного участия `seo` не требуется.
