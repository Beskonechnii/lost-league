# ТЗ 43: Импорт участников Mix Cup из гугл-таблицы

**Статус:** done · упрощённый вариант (срочно, для сборки): «капитан» из анкеты нигде не хранится
(в модели поля нет), турнир Eclipse скрипт заводит сам с дефолтами (`status: registration`, без
лимита) — вместо ручного создания через мастер
**Входит в MVP:** нет — Mix Cup целиком later (`MVP.md` §0, решение 22.09.2026); сезон открывается
лигой, а не миксом

## Цель

Оператор одной командой заливает список записавшихся из внешней формы (гугл-таблица) на турнир
формата `mixcup` так, что эти люди появляются в пуле драфта с никами, MMR и желаемыми ролями.
Закрыто, когда для турнира «Eclipse» `/admin/tournaments/<id>` показывает 42 участника, драфт их
видит, и повторный запуск скрипта дублей не создаёт.

Сейчас этого пути нет вообще: участник попадает в пул только сам, пройдя `/join/<slug>` после
входа на сайт (`src/lib/mixcup.ts` → `registerForTournament`). Регистрация Eclipse шла в телеграме,
на сайт эти 42 человека не заходили, и руками их не добавить — админка умеет только показывать
список и брать его в драфт (`admin/tournaments/_components/participants-panel.tsx`).

## Контекст

**Источник.** Гугл-таблица, лист «UNDERBEER v2.1» — экспорт анкет регистрации бота, не формат
ростера. Колонки: `Дата регистрации` · `User_id` (telegram id) · `username` (хендл) · `Игрок` (ник
в Dota) · `Позиция` (через запятую: Carry / Mid / Offlaner / Soft-support / Hard-support) · `MMR` ·
`КАПИТАН` (Да/Нет). После чистки Стасом — 42 уникальных строки (исходно 147: люди пересдавали
форму). У двух строк MMR не число (текст, ссылка на dotabuff).

**Что уже есть в коде и переиспользуется:**

- `scripts/xlsx.ts` → `loadWorkbook(src)` — принимает ссылку на гугл-таблицу, её id или локальный
  `.xlsx`; гугл качает через `export?format=xlsx`. Образец разбора листа — `scripts/sheet-to-roster.ts`.
- `src/lib/account.ts` → `createPlayerFromApplication(app, mmr, { verified: false, sourceTournamentId })` —
  существующий путь «теневого» профиля до апрува.
- `src/lib/mixcup.ts` → `registerForTournament` — обычная запись; здесь как образец порядка
  «нашли профиль → upsert записи», но вызывается не она (ей нужна анкета аккаунта, которой нет).
- `UserAccount` уже несёт ключ телеграма: `tgId` (unique), `tgUsername`, `source` (`web`/`telegram`).
  Отдельной «теневой» сущности заводить не надо — аккаунт из телеграма это штатный случай
  (`DECISIONS.md` 27.08.2026 «аккаунт лиги может жить без почты, ключом становится телеграм»).
- `TournamentRegistration(tournamentId, accountId, playerId, desiredRoles)` — единственный источник
  участников для драфта (`api/tournaments/[id]/participants`), `desiredRoles` — CSV ключей
  `src/lib/roles.ts` (ТЗ 38).
- Роли: `carry` · `mid` · `offlane` · `soft-support` · `hard-support` (`ROLES`); сборка CSV —
  `joinRoleKeys`. «Offlaner» из таблицы → `offlane`.

**Решения, на которых это стоит и которые не переигрываются:**

- `DECISIONS.md` 22.09.2026 — записавшийся на Mix Cup попадает в пул драфта **до модерации**,
  помеченный непроверенным; на `/roster/players`, в поиск и в карточку игрока он не выходит.
  Значит импортированные — `Player.verified = false` и `sourceTournamentId = <турнир>`.
- `DECISIONS.md` 23.09.2026 — Mix Cup это `Tournament(kind: "mixcup")`, консоль по праву
  `tournaments.edit`. Турнир заводится штатным мастером, скрипт его не создаёт.
- `CLAUDE.md` — `prisma/dev.db` правит только комп; скрипт запускается локально, результат едет
  в git базой, как обычно.

## Scope

**Входит:**

- Скрипт `web/scripts/import-mixcup-signups.ts` (tsx, идемпотентный, запускается руками):
  `--sheet <ссылка|id|путь.xlsx>` · `--list <вкладка>` · `--tournament <slug>` · `--dry`.
- Разбор листа в строки: telegram id, хендл, ник, роли, MMR, признак капитана.
- Сведение с базой и запись: `UserAccount` (при нужде) → `Player` (при нужде) →
  `TournamentRegistration` (upsert).
- Отчёт в консоль: сколько заведено / найдено / обновлено, блок «требует внимания» построчно.

**НЕ входит:**

- Экран массового добавления в админке — разовая заливка перед событием не окупает UI.
- Правка гугл-таблицы, дедупликация повторных анкет — чистит оператор в таблице, это уже сделано.
- Уведомление импортированным в телеграм («вы записаны») — отдельный разговор, к пулу драфта
  отношения не имеет.
- Апрув анкет импортированных и вывод их на витрины лиги — прямо запрещено решением 22.09.2026.
- Создание самого турнира Eclipse, его ассеты и оформление — мастер турниров и `MANUAL-TASKS` §7.
- Признак «хочет быть капитаном» в модели — см. «Открытые вопросы».

## Требования · DEV

**Разбор.** Шапка ищется по именам колонок, а не по номерам (столбцы в форме переставляют).
Пустая строка и строка без `Игрок` пропускаются молча. `Позиция` режется по запятой, каждое
значение нормализуется в ключ роли; «Offlaner» → `offlane`. `MMR` — целое; всё, что не парсится
в число, даёт `null` и строку в «требует внимания». `КАПИТАН` — «Да»/«Нет» без учёта регистра.

**Сведение (порядок ключей, первый сработавший выигрывает):**

1. `UserAccount.tgId == User_id` — тот же человек, что в боте.
2. `Player.telegram == username` (без `@`, регистронезависимо) — пришёл через сайт, хендл указан.
3. Никого не нашли — заводим новый аккаунт: `tgId`, `tgUsername`, `source: "telegram"`, статус по
   умолчанию (`draft`: анкеты он не подавал).

**По нику не сводим никогда** — одинаковые ники в Dota обычное дело. Если ник совпал с
существующим игроком, а ключи выше не сработали, строка идёт в «требует внимания» как возможный
дубль, но импортируется.

**Профиль.** У найденного аккаунта с `playerId`/`claimId` берём его игрока и НЕ трогаем ни ник, ни
MMR: ростер сильнее внешней формы. Профиля нет — заводим `Player`: `nickname` из `Игрок`,
`telegram` из хендла, `mmr` из формы, `mainRoles` из позиций (не больше двух — правило ТЗ 41,
лишние отбрасываются по порядку `ROLES`), `verified: false`, `sourceTournamentId` = турнир.
Слаг — общим `uniqueSlug(slugify(nickname))`.

MMR со слов игрока пишем в профиль осознанно, вопреки комментарию `createPlayerFromApplication`
(«MMR ставит оператор при апруве»): микс балансируется по нему, профиль непроверенный и на
витрины лиги не выходит.

**Запись.** `TournamentRegistration` upsert'ом по `(tournamentId, accountId)`: `playerId` и
`desiredRoles` (CSV всех отмеченных позиций) перезаписываются, повторный запуск строк не плодит.
Лимит записи (`registrationLimit`, ТЗ 39) и открытость приёма (`joinOpen`) скрипт **не проверяет**
— оператор заливает известный список, в том числе после закрытия приёма; но если после импорта
записей больше лимита, печатает предупреждение числом.

**`--dry`** печатает тот же отчёт и не пишет в базу ни одной строки.

## Acceptance criteria

- [ ] `npx tsx scripts/import-mixcup-signups.ts --sheet <ссылка> --list "UNDERBEER v2.1" --tournament <slug> --dry`
      печатает 42 разобранные строки и заканчивается строкой «записей в базу не внесено»;
      `select count(*) from TournamentRegistration` до и после не меняется
- [ ] запуск без `--dry` на том же наборе: `/admin/tournaments/<id>` показывает 42 участника,
      у каждого ник и желаемые роли из таблицы
- [ ] повторный запуск той же командой печатает 42 «обновлено», 0 «заведено», число строк
      `TournamentRegistration`, `Player` и `UserAccount` после него не меняется
- [ ] две строки с непарсящимся MMR импортированы с пустым MMR и перечислены в блоке «требует
      внимания» с исходным значением ячейки
- [ ] человек, у которого в базе уже есть аккаунт с этим `tgId` и привязанный `Player`, получает
      запись на свой существующий профиль: новый `Player` не заводится, его ник и MMR не изменились
- [ ] импортированный игрок без апрува не виден на `/roster/players` и в поиске по нику, но
      присутствует в пуле драфта турнира (`draftPool`) с ролями из таблицы
- [ ] запуск с несуществующим `--tournament` или с турниром `kind != "mixcup"` завершается
      сообщением об ошибке и ничего не пишет
- [ ] `npx tsc --noEmit` и `npm run lint` чисто, `npm run build` проходит
- [ ] права: изменений в UI нет, проверка не требуется

## Открытые вопросы

- **Капитан.** Поля под «хочет капитанить» в модели нет, капитана назначают в драфте отдельно.
  Дефолт ТЗ: желающие печатаются списком в отчёте, оператор держит его перед глазами. Если нужен
  признак прямо в консоли турнира — это правка модели и отдельный этап. Решает Стас.
- **Турнир Eclipse.** Предполагается, что он заведён мастером до импорта; нужны полное название,
  slug и лимит мест (или его отсутствие). Решает Стас.
