# ТЗ: VPS и решение по базе

**Статус:** ready
**Входит в MVP:** да — блокер релиза №1, без него публичного сезона нет вовсе.

## Цель

Лига живёт по постоянному адресу в интернете, а данные сезона переживают выкладку, перезапуск и
поломку ноутбука. По завершении: боевой адрес открывается снаружи, `git push` приводит к выкатке
без потери данных, и на вопрос «где главная база» есть один письменный ответ.

## Контекст

- Инструкция по развёртыванию — `docs/DEPLOY.md`: вариант A (Docker, рекомендуется), вариант B
  (голый Node), вариант C (таблица статикой, запасной).
- Требования к площадке жёсткие: Node 20+ и **постоянный диск**. Serverless не годится —
  база и картинки эфемерные; PHP-хостинги не годятся принципиально.
- Сейчас `web/prisma/dev.db` **коммитится** как ассет релиза (`CLAUDE.md` §3), и это работает,
  пока машина одна. Развилка описана в `docs/DEPLOY.md` → «Данные и бэкапы»: файл из репозитория
  копируется в том **только при первом запуске**, дальше сервер живёт своей копией.
- Появление аккаунтов, анкет и **личных сообщений** (`Conversation`, `ConversationMember`) меняет
  вес вопроса: в базе теперь персональные данные живых людей, и «дампнуть базу в публичный git»
  больше не нейтральное решение.
- Текстовый снимок — `npm run db:export` → `web/data/snapshot.json`, обратно `db:import`.
  Импорт работает **зеркалом**, не слиянием (`DECISIONS.md`, 23.07.2026).
- Публикация наружу сегодня — скилл `serve` (прод-контейнер + Cloudflare quick tunnel, адрес
  временный).

## Scope

**Входит:**
- Выбрать площадку и поднять на ней приложение по `docs/DEPLOY.md`, вариант A.
- Домен и HTTPS.
- Принять и **записать в `DECISIONS.md`** решение «кто главный по базе» после публикации.
- Привести репозиторий в соответствие с этим решением (что коммитится, что нет, что в `.gitignore`).
- Бэкап базы: команда, расписание, куда кладётся, как проверяется восстановление.
- Перевести бота с long polling на вебхук (`docs/archive/BOT-PLAN.md` Э9) — роут зовёт ту же
  `handleMessage`, переписывать нечего; туда же переезжает тик расписания.
- Завести на сервере `web/.env` целиком: `STEAM_API_KEY`, `TG_CHAT_ID`, `AUTH_SECRET`,
  `OWNER_EMAIL`, `GOOGLE_CLIENT_*`, `OPENAI_API_KEY`, `FRAME_ANCESTORS`.

**НЕ входит:**
- Переезд на Postgres или Turso — меняет строку подключения, а не код, и к релизу не обязателен.
- Облачное хранилище картинок — нужно только для serverless, куда мы не идём.
- CI/CD — выкатка вручную по `docs/DEPLOY.md` §6 приемлема для первого сезона.

## Требования · DEV

- Ничего в коде приложения меняться не должно, кроме вебхука бота и, если решение по базе того
  потребует, `.gitignore` и `web/README.md`.
- **Ключи только в `.env` на сервере** — ни в коде, ни в коммитах, ни в чат.
- Решение по базе описать как правило, а не как намерение: где истина, что делает `git pull`,
  что делать локальной машине, чтобы не затереть боевое.
- Личные сообщения и анкеты: если база остаётся в git, это надо либо прекратить, либо явно
  обосновать письменно. Умолчание «как было» здесь не годится.

## Требования · DESIGN

Не требуется — экранов задача не заводит.

## Требования · SEO

- Домен выбирается один и навсегда: смена адреса после индексации стоит позиций.
- HTTPS обязателен, редирект `http → https` и `www → без www` (или наоборот — но один канон).
- До открытия наружу проверить, что `FRAME_ANCESTORS` не даёт встроить сайт кому попало.
- Дальше — `docs/tasks/03-seo-bazovyi.md`.

## Acceptance criteria

- [ ] Боевой адрес открывается снаружи по https, сертификат валиден
- [ ] Перезапуск контейнера не теряет ни одной записи, заведённой через админку
- [ ] `docker compose exec -T web cat /app/data/dev.db > backup.db` отдаёт файл, и восстановление
      из него проверено **на самом деле**, а не описано словами
- [ ] Бот отвечает в телеграме при выключенном локальном `npm run bot`
- [ ] Вход через Google и вход по паролю работают на боевом адресе
- [ ] Загрузка лого команды переживает перезапуск
- [ ] В `DECISIONS.md` есть блок «кто главный по базе» с датой
- [ ] `docs/DEPLOY.md` дополнен реальными шагами этой установки, а не общими

## Открытые вопросы

- Площадку выбирает Стас. Требования — `docs/DEPLOY.md`, бюджет и провайдер не заданы.
- Судьба `dev.db` в репозитории — решение принимается здесь, вариантов два: сервер главный
  (файл из git уходит, локальная база тестовая) или локально главный (после каждой правки
  `docker compose cp`). Третьего не завозить.
