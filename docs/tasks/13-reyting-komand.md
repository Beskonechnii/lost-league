## Цель

Открыв ростер, человек за секунду видит, **кто сейчас первый** — цифрой и размером карточки,
а не вычитая это из алфавитного списка. Сегодня `/roster` (команды) и `/roster/players` (игроки)
отсортированы по имени: список лиги выглядит как справочник, а не как лига. Закрыто, когда обе
витрины отсортированы по одной понятной цифре, эта цифра подписана на карточке, а первая карточка
в списке визуально крупнее остальных.

Команд в пуле — 49, игроков — 192.

### Что из этого следует

- **Миграция не нужна ни при одном из трёх вариантов.** A и B считаются из существующих таблиц,
  C пишет строки в существующий `PointsEntry` (поля `subjectType`, `subjectId`, `tournamentId`
  уже есть). Поля `Team.rating` не заводим — по прецеденту решения 23.07.2026
  (`docs/ARCHITECTURE.md`, «Ростер»): *у команды MMR не хранится, считается по составу*. Рейтинг
  живёт там же, где standings и `teamMmr()` — в расчёте, а не в кеше.
- **Средний ранг состава как формулу не предлагаем вовсе** — у трёх игроков из четырёх ранга нет,
  цифра была бы посчитана по случайной четверти команды.

### Решения `pm`, принятые здесь и не требующие Стаса

1. **«То же для ростера» = пул игроков `/roster/players`, и рейтинг игрока новый не изобретаем.**
   У игрока в лиге уже есть ровно один рейтинг — сезонный зачёт TP (`/tournaments/<slug>/tp`,
   `src/lib/tp.ts`). Он и становится цифрой на карточке игрока и порядком в пуле. Развилка A/B/C
   касается **только команды**.
2. **Разрез — турнирный, как у TP.** Рейтинг показывает текущий турнир (`currentTournament()`);
   выбран фильтр турнира — считается по выбранному. Это уже принятый в проекте принцип
   («зачёт турнирный, в новом сезоне счёт начинается заново», `src/lib/tp.ts`), и он избавляет
   от перекоса «кто дольше в лиге, тот выше». Исключение по смыслу — вариант B: средний MMR
   состава это снимок «сейчас», турниром он не режется.
3. **Кто без рейтинга — идёт после ранжированных, с прочерком.** Команда/игрок без участия
   в выбранном турнире цифры не получает; порядок внутри этого хвоста — прежний, по имени.
4. **Крупная карточка рисуется только там, где «первый» — правда:** первая страница списка,
   пустой поиск, разрез «Сквозной». При непустом поиске и в разрезе «По турнирам»
   (`?by=tournament`) сетка ровная — иначе крупнее была бы первая строка выдачи, а не лидер лиги.

## Scope

**Входит:**

- Один расчёт рейтинга команды в новом слое `web/src/lib/team-rating.ts` — по формуле, выбранной
  в «Открытых вопросах». Один вход для всех витрин, вторых формул по месту нет.
- Порядок и цифра в **пуле команд** `/roster`: сортировка по рейтингу (убыв.), цифра и место
  подписаны на карточке.
- Порядок и цифра в **пуле игроков** `/roster/players`: сортировка по TP выбранного турнира,
  цифра и место на карточке.
- Крупная карточка первого места в обоих пулах (условия — решение 4 выше). Размер и раскладку
  задаёт `design`.
- Цифра рейтинга и место — в шапке страницы команды `/roster/teams/[id]`, теми же числами, что
  в списке.

**НЕ входит:**

- Новые поля и миграции — рейтинг считается, не хранится (решение выше, прецедент 23.07.2026).
- Таблица дивизиона `/standings/<div>` и плей-офф — там уже есть свой счёт сезона; второй таблицы
  лиги не заводим, иначе два источника правды.
- Главная, витрины внутри турнира (`/tournaments/<slug>/roster`), студия и графика анонсов —
  этап про пул ростера; расползание на все экраны превращает его в два.
- Значки TP и Spirit Shards — это **12б**, он ждёт референсов Стаса (`docs/tasks/12-grafika.md`).
  13 рисует цифру тем знаком, какой есть на момент работы, и 12б не ждёт.
- Фильтры, поиск, разрезы «Сквозной / По турнирам», пул/архив, удаление команд, `PoolSwitch` —
  механизмы из прежних этапов (решения 28.08.2026 и 04.09.2026), трогается только порядок и карточка.
- История рейтинга, движение «было → стало», графики — отдельный разговор, вводных нет.
- Начисление рейтинга руками из админки — только если выбран вариант C (тогда он и появится
  в scope при переводе ТЗ в `ready`).

## Требования · DEV

- **Слой один:** `web/src/lib/team-rating.ts` — серверная функция «турнир → Map<teamId, {score, place}>»
  плюс чистый расчёт очков, если он не сводится к готовому `seriesPoints()`. Витрины и страница
  команды ходят только в неё.
- **Игроки переиспользуют `tpByTournament()`** из `src/lib/tp.ts`. Второго расчёта TP не заводить.
- **Порядок и место считаются на сервере** и приезжают в `PoolExplorer` / `PlayersExplorer` готовыми:
  поиск и фильтр там клиентские, и пересчёт места в клиенте разъедется с серверным списком.
- **Равные очки** — порядок стабильный: при равенстве сортируем по имени (`localeCompare`), иначе
  список прыгает между перерисовками. Место при равенстве — одинаковое число у обоих
  (место 1, 1, 3), а не произвольный порядок.
- `listPoolTeams()` / `listPoolPlayers()` отдают новые поля в существующих типах (`TeamCard` и
  карточка игрока); новых выборок в страницах не появляется.
- Права: обе витрины публичные, читаются гостем. Ничего нового под правом не появляется.

## Acceptance criteria

Формула-независимые — проверяются при любом ответе Стаса:

- [ ] `/roster` без фильтров: карточки идут по убыванию показанной цифры; у первых трёх карточек
      цифра не возрастает сверху вниз
- [ ] первая карточка `/roster` крупнее любой следующей в той же сетке (измеряется шириной или
      высотой элемента, а не на глаз)
- [ ] ввод в поиск на `/roster` → крупной карточки нет, все карточки одного размера
- [ ] `/roster?by=tournament` → крупной карточки нет, все карточки одного размера
- [ ] `/roster/players` без фильтров: порядок по убыванию TP текущего турнира; цифра на карточке
      совпадает с числом того же игрока в `/tournaments/<slug>/tp`
- [ ] команда без участия в выбранном турнире показана ниже всех ранжированных, цифра — прочерк
- [ ] цифра и место на карточке команды в `/roster` совпадают с цифрой и местом в шапке
      `/roster/teams/[id]` той же команды
- [ ] две команды с равными очками идут в алфавитном порядке и получают одинаковый номер места;
      перезагрузка страницы порядок не меняет
- [ ] гость (без входа) видит обе витрины с рейтингом; ни одна цифра не требует прав
- [ ] `npx tsc --noEmit` и `npm run lint` чисто, `npm run build` проходит
- [ ] 390px, **1280px** и 1440px без горизонтального переполнения — включая ряд, где крупная
      карточка стоит рядом с обычными
- [ ] в схеме Prisma нет изменений (`git diff web/prisma/` пуст), новых миграций нет

Критерии на саму формулу (что именно считается, на каких данных, какой результат у контрольной
команды) `pm` дописывает после ответа по развилке — до него они были бы придуманы за Стаса.
