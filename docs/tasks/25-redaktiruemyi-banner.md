# ТЗ 25: Редактируемый баннер главной

**Статус:** ready
**Входит в MVP:** нет — баннер уже говорит правду по данным, сезон открывается без редактора

## Цель

Организатор меняет первый экран лиги сам, не через `stage`: картинку, заголовок, подпись и кнопку.
Сегодня герой выбирается кодом по состоянию данных (идёт приём → зови заявляться, гость → зови
вступать, иначе → анонсы), и любое «повесить на главную другое» стоит правки файла и выкатки.
Закрыто, когда оператор с нужным правом меняет все четыре элемента из админки и видит результат
на `/` без участия разработчика.

## Контекст

- `web/src/app/(home)/banner.tsx` — три ветки героя (`HomeBanner`) и общий `Banner({icon, eyebrow,
  title, text, cta})`. Полотно сейчас не картинка, а акцентная плашка с именем лиги и подписью
  «Киберспортивная лига · Минск»; на ней же единственный `<h1>` страницы.
- Ветка приёма заявок берёт турнир из `openForRegistration()` (`lib/tournaments.ts:254`).
- Загрузки файлов в проекте есть: `web/public/uploads/`, правила — `CLAUDE.md`, «Конвенции»
  (вывод генерации лежит отдельно и в git не идёт).
- Решение Стаса 16.09.2026: **вариант B** — правится картинка **и** текстовая часть (заголовок,
  подпись, кнопка).
- Раздела «Новости» в проекте нет и в этой работе не заводится.

## Scope

**Входит:**
- Один баннер главной, который редактирует оператор: изображение, заголовок, подпись, надпись
  кнопки и её адрес.
- Экран правки в служебной части, под правом из существующего набора (`lib/permissions.ts`),
  нового права не заводим.
- **Запасной ход:** баннер не заполнен или выключен — главная показывает нынешний герой по данным
  (приём заявок → анонс). Пустой первый экран лиги недопустим.
- Заголовок страницы: `<h1>` главной остаётся ровно один и после правки баннера.

**НЕ входит:**
- Раздел «Новости» и лента материалов — это отдельный продукт, а не поле в баннере.
- Несколько баннеров, ротация, показ по расписанию — сначала нужен один управляемый.
- Правка остальных плит главной (турниры, матчи, баллы) — они живут данными, а не текстом.
- Генерация картинки в студии — студия `later` (`DECISIONS.md` 02.09.2026).

## Требования · DEV

- Содержимое баннера хранится в БД, а не в файле в репозитории: правка оператора не должна
  требовать коммита и выкатки (ровно та цена, ради которой работа затевается).
- Изображение кладётся в `public/uploads/` по правилам проекта; ссылка на файл хранится вместе
  с остальными полями баннера.
- Пустые поля не «подставляются заглушкой»: пусто — работает ветка по данным целиком, а не
  наполовину (иначе на главной окажется чужой заголовок с чужой кнопкой).
- Адрес кнопки принимается и внутренний, и внешний; внешний открывается как внешний.

## Требования · DESIGN

Заполняет роль `design`: место картинки в герое (сейчас там акцентная плашка с именем лиги),
пропорции и поведение при картинке другого размера, длина заголовка и подписи, при которой
раскладка не рвётся, вид формы правки в админке, состояние «баннер не задан».

## Требования · SEO

Заполняет роль `seo`: `<h1>` главной — одна штука, и она должна остаться осмысленной при любом
тексте баннера; alt у картинки; влияние на OG главной. Экран правки — `/admin`, не индексируется.

## Acceptance criteria

- [ ] Оператор с правом открывает экран правки баннера из хаба админки и видит четыре поля
      (заголовок, подпись, надпись кнопки, адрес кнопки) и загрузку картинки.
- [ ] После сохранения `/` показывает новый заголовок, новую подпись и кнопку с новой надписью;
      нажатие кнопки ведёт по заданному адресу.
- [ ] После загрузки картинки она видна в герое на `/`; файл лежит в `public/uploads/`.
- [ ] Баннер очищен (или выключен) → `/` показывает прежний герой по данным: при открытом приёме
      заявок — призыв заявиться в турнир из `openForRegistration()`.
- [ ] Внешний адрес кнопки открывается в новой вкладке, внутренний — переходом внутри сайта.
- [ ] Аккаунт без права экран правки не открывает (прямой заход даёт отказ), плитки на хабе не видит.
- [ ] На `/` ровно один `<h1>` при любом состоянии баннера.
- [ ] `npx tsc --noEmit` и `npm run lint` чисто, `npm run build` проходит.
- [ ] 390px, **1280px** и 1440px без горизонтального переполнения — и на главной, и на экране правки.
