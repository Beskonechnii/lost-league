# ТЗ: недостающие атомы Кита в код

**Статус:** сделано — оба подэтапа приняты qa (A — 2ace973, B — e220263)
**Входит в MVP:** нет — ни одна из 24 публичных страниц без этих атомов не ломается; ни один из
блокеров Б1–Б4 (`MVP.md` §3) ими не закрывается. Берётся в работу после открытия сезона.

## Цель

В макете «Кит элементов» (45 артбордов) есть семь атомов, которых нет в `web/src/components/pouf/`.
Пока их нет, каждый новый экран решает те же задачи по месту — как уже случилось с крошками
(`web/src/app/_components/breadcrumbs.tsx`) и с радио в заявке. Задача закрыта, когда семь атомов
живут в Ките с теми же состояниями, что на листе, а локальные копии из `app/` выпилены.

## Контекст

- Макет: `design/kit/parts/<Имя>.html` — разметка листа, `<Имя>.css` — хвост стилей листа.
  Сборка `.dc.html` — `design/kit/build.mjs`. Опубликованный канвас:
  https://claude.ai/code/artifact/de74082f-62a9-46ca-b381-b12a204ab6d1
- Кит в коде: `web/src/components/pouf/` — 38 файлов, ~100 экспортов. Токены — `pouf/pouf.css`,
  Tailwind v4, светлая тема Light Clay.
- Правило проекта (`CLAUDE.md` → Конвенции): **новый компонент заводится в Ките, а не по месту.**
- Что уже есть и мешает делать «с нуля»:
  - `pouf/date-field.tsx` — внутри поповера уже нарисована месячная сетка (`grid-cols-7`,
    переключение месяца/года). Артборд `Calendar.html` — это она же, вынесенная наружу.
  - `pouf/checkbox.tsx` — образец для `Radio`: та же обвязка, другой индикатор.
  - `pouf/Segmented.tsx` — это НЕ тумблер. `ToggleGroup` в `pouf/Button.tsx` упомянут только
    в комментарии, кода нет.
  - `app/_components/breadcrumbs.tsx` — рабочие крошки по месту, потребители:
    `(public)/series/[slug]`, `(public)/players/[key]`, `(public)/roster/teams/[id]`,
    `(public)/chat/[playerId]`, `(public)/chat/system`.
  - `(public)/tournaments/[slug]/apply/board-slots.tsx:99` — нативный `type="radio"`.
- Грабли: клиентские хуки в файле, который импортирует серверный компонент, ловит только
  `npm run build`, не `dev` (см. `pouf/password-field.tsx`).

## Scope

**Входит** — семь атомов, единица работы «один артборд → один экспорт в `pouf/`»:

Подэтап A · формы
- `Radio` — `design/kit/parts/Radio.html`: on / off, плюс disabled и focus по образцу `checkbox.tsx`.
  Нативный `type="radio"` в `(public)/tournaments/[slug]/apply/board-slots.tsx:99` заменяется на него
  (решение Стаса 12.09.2026): поведение выбора слота не меняется, меняется только вид.
- `Toggle` — `Toggle.html`: off / on / on+focus, подпись слева, состояние disabled.
- `Calendar` — `Calendar.html`: шапка (стрелки месяца, дропдауны месяца и года), сетка 7 колонок,
  дни вне месяца приглушены, выбранный день. Выносится из `date-field.tsx` отдельным экспортом,
  `DateField` начинает использовать его.

Плюс витрина атомов — маршрут `/admin/kit` (решение Стаса 12.09.2026). Заводится в подэтапе A
вместе с первыми тремя атомами, в подэтапе B дополняется четырьмя остальными: каждый атом
попадает на витрину тем же коммитом, что и заводится, иначе она отстанет.

Подэтап B · навигация и подсказки
- `Breadcrumbs` — `Breadcrumbs.html`: переезд `app/_components/breadcrumbs.tsx` в `pouf/`,
  импорты у пяти потребителей переписываются, старый файл удаляется.
- `Pagination` — `Pagination.html`: стрелки, номера, многоточие-разрыв; состояния default / hover /
  press / current.
- `Tooltip` — `Tooltip.html`: подсказка над элементом.
- `Accordion` — `Accordion.html`: элемент свёрнут / раскрыт, шеврон меняет направление.

**НЕ входит:**
- **Сверка состояний у 38 уже реализованных листов** (ButtonSolid/Quiet/Icon, TextField, Select,
  Menu, Chip, StatTile, SeriesCard, Standings, RankMedal, SheetPanel, Skeleton, EmptyState,
  TournamentStatus и прочие) — это ревизия объёмом с отдельное ТЗ, а не перенос; строка в `BACKLOG.md`.
- **Внедрение новых атомов в существующие экраны** (кроме пяти потребителей крошек, `DateField`
  и радио в заявке) —
  замена рабочей вёрстки на публичных страницах перед сезоном даёт риск без выигрыша.
- **Артборды «Осколки» и «Скорборд»** — их нет в макете; это правка артефакта, не кода
  (`BACKLOG.md`, later).
- **Тёмная тема** — атомы пишутся на токенах, переопределение палитры отдельным блоком (`MVP.md` §2).

## Требования · DEV

- Каждый атом — экспорт из `web/src/components/pouf/`, именование файлов как у соседей
  (`radio.tsx`, `toggle.tsx`, `calendar.tsx`, `breadcrumbs.tsx`, `pagination.tsx`, `tooltip.tsx`,
  `accordion.tsx`). Класть несколько атомов в один файл можно, только если они делят разметку.
- Цвета, радиусы, тени — токенами из `pouf/pouf.css`. Хардкод hex из `parts/*.html` не переносится:
  в артборде он стоит вместо токена.
- Состояния задаются через варианты/пропсы и `:hover` / `:active` / `:focus-visible` / `disabled`,
  а не копией разметки на каждое состояние.
- `Calendar` не тянет за собой состояние `DateField`: дата приходит пропсом, выбор уходит колбэком.
- `Breadcrumbs` сохраняет текущий API (`items: {href, label}[]`), чтобы переезд был переименованием
  импорта, а не правкой пяти страниц.
- Подэтапы A и B сдаются отдельно и коммитятся отдельно.
- Витрина `/admin/kit` — страница в группе `(admin)`, по секции на атом: название, все состояния
  живыми компонентами (не картинкой), строка со ссылкой на лист канваса. Данных и прав не
  требует, в навигацию админки не выводится — адрес известен тем, кто с Китом работает.
  Витрина ПОКАЗЫВАЕТ соответствие коду; источник вида остаётся канвас Кита.
