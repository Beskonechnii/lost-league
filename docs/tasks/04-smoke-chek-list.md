# ТЗ: smoke-чек-лист перед релизом

**Статус:** ready
**Входит в MVP:** да — блокер релиза №4. Это приёмка сезона целиком, а не отдельной фичи.

## Цель

Перед открытием публичного сезона пройден один и тот же список проверок по всем живым сценариям,
и по каждому пункту есть честный pass/fail. По завершении: список лежит в репозитории и
прогоняется перед каждой выкладкой, а не сочиняется заново.

## Контекст

- Чек-лист нового раздела уже есть — `docs/UI-GUIDELINES.md` §8; эта задача не заменяет его,
  а добавляет прогон по продукту целиком.
- Ширины проверки: **390px** (телефон) и **1440px** (десктоп) — мобильный проход описан в
  `docs/UI-GUIDELINES.md` §6.
- Права: реестр инструментов и прав — `web/src/app/_components/tools.ts`, роли —
  `DECISIONS.md` от 12.08.2026 и 04.09.2026.
- Известная грабля проверки: dev-сервер на `127.0.0.1` отдаёт мёртвую разметку (Next 16 блокирует
  dev-ресурсы для хоста не из `allowedDevOrigins`) — проверять только через `localhost`
  или на боевом адресе (`BACKLOG.md`).
- Порт 3000 часто занят сервером Стаса — поднимать своим (`npm run dev` сам уйдёт на 3001+).

## Scope

**Входит:**
- Написать файл `docs/SMOKE.md` — список сценариев с отметками, пригодный к повторному прогону.
- Прогнать его целиком на боевом адресе после `docs/tasks/01-vps-i-baza.md`.
- Завести роль `qa` как исполнителя этого прогона.

**НЕ входит:**
- Автотесты — их в проекте нет и заводить их этой задачей мы не начинаем.
- Нагрузочное тестирование — у лиги десятки одновременных зрителей, не тысячи.

## Требования · DEV

Кода задача не меняет. Если прогон находит дефект — он заводится строкой в `BACKLOG.md` или
отдельным ТЗ, а не чинится внутри приёмки.

## Требования · DESIGN

Проверка вёрстки идёт по `docs/UI-GUIDELINES.md` §8: уровни навигации, скелет страницы,
ширины по токенам, состояния пусто/загрузка/ошибка.

## Требования · SEO

Пункты индексации входят в прогон: `robots.txt`, `sitemap.xml`, `noindex` на служебном,
превью ссылки в телеграме — см. `docs/tasks/03-seo-bazovyi.md`.

## Acceptance criteria

Сценарии, которые обязаны быть в `docs/SMOKE.md` и пройти:

**Гость**
- [ ] Главная открывается, блоки не пустые, «Войти» на месте
- [ ] Турнир → дивизион → таблица → встреча → отчёт матча проходятся ссылками без тупика
- [ ] Профиль игрока и страница команды открываются, медаль ранга и составы на месте
- [ ] `/roster` в обоих разрезах, поиск по лиге что-то находит
- [ ] Битый адрес даёт наш 404, а не системную страницу Next

**Новый игрок**
- [ ] Регистрация по почте и паролю; слабый пароль отвергается внятным текстом
- [ ] Анкета проходится целиком; уход со страницы на середине не теряет ответы
- [ ] Привязка Steam и привязка телеграма проходят и отражаются в профиле
- [ ] После отправки виден welcome, а не тупик
- [ ] Сброс пароля работает (`docs/tasks/02-sbros-parolya.md`)

**Капитан**
- [ ] Заявка команды в турнир собирается из пула и отправляется
- [ ] Игроки состава получают запрос согласия и могут ответить
- [ ] Заказ встречи через бота доходит до соперника и до организатора

**Оператор**
- [ ] Апрув заявки заводит команду, игроков и состав
- [ ] Правка счёта встречи отражается в таблице дивизиона
- [ ] Импорт составов и импорт CRM проходят на `--dry` без ошибок

**Права (главное)**
- [ ] Чужой профиль не редактируется — ни формой, ни прямым POST
- [ ] Чужой чат не открывается по прямой ссылке на комнату
- [ ] Админ **без** конкретного права получает отказ и на странице, и в server action
- [ ] Гость, зашедший на `/admin/*`, не видит данных и получает отказ, а не пустой экран
- [ ] Куки удалённого аккаунта недостаточно, чтобы что-то сделать

**Техника**
- [ ] `npx tsc --noEmit`, `npm run lint`, `npm run build` — чисто
- [ ] 390px: ни одна страница продукта не скроллится горизонтально
- [ ] 1440px: колонки не разъезжаются, максимальные ширины по токенам
- [ ] В консоли браузера нет своих ошибок на ключевых экранах
- [ ] Перезапуск сервера не теряет данных

## Открытые вопросы

- Нужен ли прогон под реальной учёткой игрока: под разработчиком часть экранов недоступна —
  на Э21 это уже мешало проверке мини-профиля. Скорее всего нужна тестовая учётка на боевом,
  заводить её заранее.
