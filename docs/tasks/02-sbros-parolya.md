# ТЗ: сброс пароля без писем

**Статус:** ready
**Входит в MVP:** да — блокер релиза №2. Забыл пароль = потерял аккаунт навсегда.

## Цель

Игрок, забывший пароль, возвращает себе доступ сам или в одно обращение к организатору — не заводя
второй аккаунт. По завершении: у каждого способа входа есть путь восстановления, и ни один из них
не открывает чужой аккаунт.

## Контекст

- Почтового флоу в проекте **нет**: он удалён сознательно (`DECISIONS.md`, 20.08.2026), ключей
  почты в `.env` больше нет. Значит классическая «ссылка на почту» недоступна.
- Крипта в порядке и не трогается: `web/src/lib/password.ts` — scrypt, соль на пароль,
  `timingSafeEqual`. Правила — `web/src/lib/password-rules.ts` (Э16).
- Смена пароля вошедшим уже есть: `web/src/app/(public)/me/settings/security-forms.tsx` +
  `me/settings/actions.ts`.
- Лимит попыток входа есть: `web/src/lib/rate-limit.ts`, 10 неудач за 15 минут на пару «почта+IP».
- Есть два доверенных канала, которых нет у почты: **телеграм** (привязка ботом, Э19,
  `web/src/lib/tg-link.ts`, `tgId` у аккаунта) и **вход по одноразовому коду** `/login/tg`.
- Есть роли и права: владелец и админы, реестр прав — `web/src/app/_components/tools.ts`.
- Известная дыра рядом: у аккаунта, пришедшего из бота, почты нет вовсе, и `loginWithPassword`
  ищет по почте — «задать пароль» такому аккаунту входа не даёт (`BACKLOG.md`). Здесь решается
  или явно откладывается.

## Scope

**Входит:**
- Самостоятельный сброс через телеграм: у кого привязан `tgId` — бот присылает одноразовый код
  или ссылку, по ней задаётся новый пароль.
- Сброс оператором из админки: владелец и админ с правом выдают одноразовую ссылку/код на смену
  пароля конкретному аккаунту. Оператор **не видит и не задаёт** пароль сам.
- Запись в аккаунт: факт сброса, кто инициировал, когда.
- Инвалидация: после смены пароля прежние сессии аккаунта перестают действовать.

**НЕ входит:**
- Восстановление через почту — писем приложение не шлёт, возвращать почтовый флоу ради этого
  дороже, чем сделать два пути выше.
- Секретные вопросы — они слабее пароля, который защищают.
- Привязка почты к аккаунту из бота — отдельная задача, здесь только упоминается.

## Требования · DEV

- Токен сброса — одноразовый, с коротким сроком (15–30 минут), один живой на аккаунт.
  Образец уже есть: `TgLinkToken` (`web/src/lib/tg-link.ts`) — брать ту же механику, а не
  придумывать вторую.
- Новый пароль проходит `passwordProblem()` из `password-rules.ts` — те же правила, что при
  регистрации. Второго набора правил не заводить.
- Сброс через оператора **не должен** становиться способом залезть в чужой аккаунт: действие
  логируется, и у аккаунтов с ролью `owner` сброс оператором недоступен.
- Рейт-лимит на запрос сброса — через `createLimiter` из `rate-limit.ts`, не своей реализацией.
- Формы — компоненты Кита (`pouf/`), `PasswordField` уже есть.

## Требования · DESIGN

- Экран «Забыли пароль?» — на двери `/me` (`me/door.tsx`), ссылкой под формой входа; окно входа
  собрано на `pouf/auth.tsx`, отдельной вёрстки не заводить.
- Три состояния экрана: запрос → «мы отправили в телеграм» → форма нового пароля.
  Четвёртое — «у аккаунта нет телеграма, обратитесь к организатору» с понятным текстом.
- **Ответ на запрос сброса одинаков вне зависимости от того, есть такой аккаунт или нет** —
  иначе форма превращается в проверялку чужих почт.
- Раздел оператора — в существующем экране аккаунта админки, не новым пунктом сайдбара.
- 390px и 1440px, состояния «истёк токен» и «токен уже использован» — экранами, не алертом.

## Требования · SEO

- Все страницы сброса — `noindex, nofollow`. Публичной ценности нет, индексировать нечего.
- Ссылка с токеном не должна утекать в реферер на внешние ресурсы.

## Acceptance criteria

- [ ] Игрок с привязанным телеграмом сбрасывает пароль сам и входит новым
- [ ] Игрок без телеграма видит внятный текст, что делать, и контакт организатора
- [ ] Оператор выдаёт ссылку сброса, но нигде не видит пароля
- [ ] Сброс аккаунта владельца оператору недоступен
- [ ] Токен одноразовый: повторный переход по той же ссылке — отказ
- [ ] Истёкший токен (>30 мин) — отказ с предложением запросить заново
- [ ] Ответ на запрос для несуществующей почты неотличим от ответа для существующей
- [ ] Новый пароль короче 10 символов или из чёрного списка — отвергается тем же текстом, что при регистрации
- [ ] После смены пароля прежняя сессия разлогинена
- [ ] `npx tsc --noEmit`, `npm run lint`, `npm run build` — чисто
- [ ] 390px и 1440px без горизонтального переполнения
