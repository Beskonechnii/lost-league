# ТЗ 46: Лист контрольных кадров экрана

**Статус:** qa · сделано 26.09.2026, лист снят на dev — ждёт приёмки
**Входит в MVP:** нет — это инструмент нашего процесса, а не продукт. Сезон открывается без него:
ни одна публичная страница, ни один блокер Б1–Б4 от листа кадров не зависят. Экономит он наше
время на правках вёрстки, а не игру игрока

## Цель

Замечания по вёрстке собираются **одним листом**: запускаем скрипт, получаем один PNG со всеми
нужными экранами на нужных ширинах и подписями, Стас пишет список правок сразу по всему листу.
Это закрывает правило `CLAUDE.md` «вёрстку правим пачкой, не по одной мелочи» и разбор
`docs/PROCESS-REVIEW.md` §4: двадцать кругов «правка → сборка → превью» на один экран мы уже
проходили. Поймём, что закрыли, когда следующий заход по вёрстке начнётся с листа и списка
замечаний, а не с открывания страниц по одной.

## Контекст

- Рендер уже есть: `web/src/lib/render-png.ts` — `renderUrlToPng(url, { width, height, selector,
  scale, timeoutMs })`. Playwright — devDependency (`package.json:51`), тянется ленивым `import`
  внутри функции, браузер ставится один раз: `npx playwright install chromium`.
- Скрипты проекта: `web/scripts/*.ts` под `tsx`, запускаются руками, идемпотентны, в рантайм не
  тянутся (`CLAUDE.md` §Конвенции). Пример работы с рендером — `scripts/send-infographic.ts`.
- Служебные экраны снимаются вошедшим: `DEV_LOGIN_EMAIL` подставляет сессию аккаунта с этой почтой,
  когда куки нет (`web/src/lib/player-session.ts:62-78`, пропуск в `web/src/proxy.ts:16`), вне
  production. Переменная — в `web/.env` (шаблон `web/.env.example:41`).
- Порт dev — **3000**, 3001 занят контейнером `serve`. UI проверяется только через `localhost`:
  на `127.0.0.1` Next 16 блокирует dev-ресурсы и гидрация не проходит.
- Вывод — не ассет: `public/uploads/generated/` и `uploads/postgame/` уже в `.gitignore` по тому же
  принципу «вывод, а не ассет».

## Scope

**Входит:**

- Скрипт в `web/scripts/` (имя-предложение — `screen-sheet.ts`), запускается руками, идемпотентен.
- Список экранов — **конфигом**, не хардкодом в теле скрипта: набор правится без правки логики.
  У экрана задаются адрес, ширины и признак «нужен вход».
- Ширины: 390 / 1280 / 1440 для продуктовых экранов, 1920×1080 для оверлеев — у каждого экрана свои.
- Возможность снять подмножество одним запуском (аргумент вида `--only=home,tournaments`), чтобы
  проверить правку одного экрана без полного листа.
- Склейка кадров в **один PNG** с подписью под каждым: адрес и ширина.
- Вывод в папку вне `public/`, добавленную в `.gitignore` — лист не раздаётся по HTTP и не
  коммитится.
- Прогон не падает на первом сбое: недоступный экран пропускается с причиной в stdout, лист
  собирается из остальных.
- Путь готового листа печатается в stdout.

**НЕ входит:**

- Сравнение с эталоном и визуальный регресс-диф — это тест, тестов в проекте нет и инфраструктуру
  под них этим ТЗ не заводим.
- Запуск в CI / по коммиту — скрипт руками, как все в `scripts/`.
- Съёмка прод-адресов — снимаем локальный dev; боевой сайт проверяет `qa` по `docs/SMOKE.md`.
- Состояния, которых нельзя получить адресом (открытый диалог, наведение, ошибка формы после
  отправки) — лист снимает URL; такие состояния — отдельный заход, если окажутся нужны.
- Поднятие dev-сервера самим скриптом — два dev-сервера в одной папке Next 16 запрещает, скрипт
  не должен угадывать, что уже запущено.
- PDF, HTML-галерея, страница просмотра листа в приложении — результат один PNG.
- Заведение скилла — см. «Открытые вопросы», это решение Стаса, а не часть кода.

## Требования · DEV

- Переиспользовать `renderUrlToPng` (`web/src/lib/render-png.ts`). Нужна пачка кадров за один
  запуск браузера — **расширить утилиту**, а не завести вторую обёртку над Playwright.
- Базовый адрес — аргумент со значением по умолчанию `http://localhost:3000`. Только `localhost`,
  не `127.0.0.1` (иначе кадр снимется с неработающей гидрацией и соврёт).
- Dev-сервер не запущен — внятное сообщение «подними `npm run dev`» и ненулевой код выхода,
  а не таймаут Playwright со стеком.
- Экраны с признаком «нужен вход» снимаются сессией `DEV_LOGIN_EMAIL`. Переменная пустая — скрипт
  говорит об этом строкой и не выдаёт молча страницу входа как готовый кадр.
- Чем клеить кадры в лист — решает `stage`; внешние сервисы и новые тяжёлые зависимости не
  заводить, если задачу закрывает уже установленное.
- Скрипт вне рантайма: из `src/` его не импортируют, в бандл он не попадает.

## Требования · DESIGN

Не требуется — лист служебный. Единственное требование к виду: подпись под кадром читается при
масштабе 100 % и содержит адрес и ширину.

## Требования · SEO

Не требуется — публичных страниц и адресов не добавляется.

## Acceptance criteria

- [ ] `npm run dev` поднят на 3000 → запуск скрипта без аргументов создаёт **один** PNG, в нём есть
      кадр каждого экрана конфига на каждой заданной ширине.
- [ ] Последней строкой stdout напечатан путь к листу; файл по этому пути существует.
- [ ] Под каждым кадром подпись с адресом и шириной в пикселях.
- [ ] Повторный запуск с тем же конфигом перезаписывает лист: второго файла и промежуточного
      мусора в папке вывода не появляется.
- [ ] Запуск с `--only=<один экран>` даёт лист ровно с этим экраном.
- [ ] Экран с признаком «нужен вход» (например `/admin`) снят содержимым для вошедшего: на кадре
      хаб админки, а не форма входа.
- [ ] `DEV_LOGIN_EMAIL` пуст → в stdout строка про это по каждому такому экрану; кадр входа не
      выдаётся как результат молча.
- [ ] Оверлей снят 1920×1080, на кадре виден борд (команды и пул), а не пустая сцена.
- [ ] Заведомо битый адрес в конфиге: прогон доходит до конца, лист собран из остальных экранов,
      в stdout строка с причиной по битому.
- [ ] Dev-сервер погашен → сообщение с подсказкой поднять `npm run dev`, ненулевой код выхода,
      без стека Playwright.
- [ ] После прогона `git status` чист: лист и папка вывода не видны git.
- [ ] Список экранов меняется правкой конфига: добавленный адрес попадает в лист без правки кода
      скрипта.
- [ ] `npx tsc --noEmit` и `npm run lint` чисто. `npm run build` этим ТЗ не затрагивается —
      скрипт вне рантайма, но должен остаться проходящим.
- [ ] Права: скрипт не меняет доступов приложения; `DEV_LOGIN_EMAIL` не действует в production
      (существующий замок `player-session.ts:67`) — проверяется чтением, кодом не трогается.
