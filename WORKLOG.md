## 2026-08-26 — Работа с двух устройств: скиллы pickup и handoff

**Зачем.** Работа идёт то с компа, то с телефона (облачная сессия — отдельный контейнер со своим
клоном). Контейнер живёт недолго: всё, что не в git, теряется. Нужен повторяемый порядок входа
и выхода, чтобы не проговаривать его каждый раз.

**Решения (Стас):** облачная сессия **не трогает `dev.db`** — бинарник не мержится, база остаётся
заботой компа; сессия заканчивается **пушем ветки и PR в `main`**, а не прямым мержем.

**Сделано:**
- Скилл **`pickup`** — начало сессии: `git fetch --prune`, разбор расхождений (отставание,
  незакоммиченное, забытые ветки `claude/*` с их PR), чтение верхней записи `WORKLOG.md`,
  короткая сводка. Состояние берётся из git, а не из памяти чата.
- Скилл **`handoff`** — конец сессии: проверка `dev.db` → запись в `WORKLOG.md` → `ship`
  (коммит + пуш) → PR в `main` → памятка с командами для другой стороны.
- **Починен агент `ship`:** все команды шли с `-C "League-of-spirit"` — путь с компа, в облачной
  сессии папка называется `LOST` и лежит по другому пути, то есть скилл там просто не работал.
  Теперь корень определяется через `git rev-parse --show-toplevel`. Заодно поправлен устаревший
  remote (`League-of-spirit` → `LOST`) и добавлено правило про `dev.db` в облаке
  (маркер среды — `$CLAUDE_CODE_CONTAINER_ID`).
- Правило «Телефон ↔ компьютер» в `CLAUDE.md`, чтобы порядок действовал и без вызова скилла.

**Файлы:** `.claude/skills/{pickup,handoff}/SKILL.md`, `.claude/skills/ship/SKILL.md`,
`.claude/agents/ship.md`, `CLAUDE.md`.

**Дальше:** порядок обкатывается этой же записью — она сделана скиллом `handoff`. Ближайшая работа
по коду не начата: следующий кандидат — статистика игрока в разрезе турниров (`BACKLOG.md` §2).

## 2026-08-23 — Модерация: заявка на привязку падала во вкладку анкет

**Причина:** списки резались по статусу аккаунта, а не по виду заявки. `pendingClaims` исключал

**Сделано:**
- Режем по виду заявки: `pendingRegistrations` — `pending` **и без claim** (только анкеты),

- Одобрение привязки теперь идёт через тот же `approveRegistration` (ставит `playerId` из `claimId`
  и открывает аккаунт) — прежний `approveClaim` только привязывал и оставлял аккаунт в `pending`,
  то есть из воронки он бы не вышел. Функцию убрал, чтобы не было двух «пустить в лигу».
- Отказ развели по последствиям: `rejectClaim` для аккаунта в `pending` уходит в `rejectRegistration`
  (статус `rejected` + причина в кабинет), для открытого аккаунта просто снимает `claimId` — из лиги
  его никто не выгонял. В форме у второго случая поля причины нет, кнопка «Отклонить».
- `ReviewForms` получил флаги `link`/`reasonRequired`; карточка вкладки анкет упростилась —
  ветки claim в ней больше нет.
