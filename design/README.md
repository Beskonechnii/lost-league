# design/ — макеты LOST

## Принцип: атомы в одном месте, экраны — отдельно

- **Атомы (кнопки, поля, переключатели, бейджи, свитчер темы, …) → один кит** `kit/`
  («Кит элементов»). Это единый источник элементов и рецептов (STYLE). Новый элемент
  заводится **здесь**, а не в отдельном ките — иначе плодятся дубли.
- **Экраны и секции (сайдбар, будущие страницы) → свой канвас**, но на рецептах кита:
  их `build.mjs` переиспользует `STYLE` из `kit/build.mjs` (см. `sidebar/build.mjs`).
  Так «одно место» соблюдается на уровне элементов и STYLE, а кит не распухает
  композициями. Композиция берёт готовый атом из кита, а не рисует свой.


Экраны: `sidebar/` (сайдбар), `home/` (главная, генератор `home/build.mjs`, артефакт
https://claude.ai/code/artifact/d0b1862a-d038-4b21-adc5-1fc250458bac) — цикл правки тот же.

Канонический макет — **`kit/`** («Кит элементов», Light Clay). Артефакт-превью:
https://claude.ai/code/artifact/de74082f-62a9-46ca-b381-b12a204ab6d1

## Что где

- `kit/build.mjs` — общий `STYLE` (pouf-рецепты) и сборка: складывает каждый лист из `parts/`.
- `kit/parts/<Имя>.html` — **разметка листа, источник истины**. Рядом `<Имя>.css` — хвост CSS,
  нужный только этому листу; `<Имя>.solo.css` — лист со своим стилем, общий `STYLE` ему не
  подмешивается (так живёт `RankMedal`).
- `kit/*.dc.html` — вывод генератора, 45 артбордов, руками не правятся. Регенерация: `node build.mjs`.
- `kit/canvas.json` — раскладка артбордов на канвасе + аннотации.
- Собранный `lost-clay-kit.html` (~2.6MB) — вывод сборки канваса, в git **не** коммитим.

## Цикл правки

1. Правим `kit/parts/<Имя>.html` (или `<Имя>.css`); новый лист — новая пара файлов плюс
   строка в `canvas.json`. Общие рецепты — в `STYLE` внутри `build.mjs`.
2. `cd design/kit && node build.mjs` — перезапишет все `.dc.html`.
3. Скилл `design` пересобирает канвас из `.dc.html` + `canvas.json`:
   `node <база скилла>/seed-canvas.mjs --template <база>/payload.template.html
   --out lost-clay-kit.html --title "LOST · Кит элементов" --canvas canvas.json --artboard <каждый>.dc.html`,
   затем `--check`.
4. Публикуем **по тому же URL** артефакта (`Artifact url=…`, `contract: "0.1.31"`,
   `capabilities` не передаём — канвас держит своё), новый не плодим.

**Правил в канвасе — верни в `parts/`.** Артборд, заведённый прямо в канвасе, генератору
неизвестен, и первая же пересборка его сотрёт. Достать обратно:
`seed-canvas.mjs --extract <сохранённая страница> --to <пустая папка>` даёт `.dc.html` и
`canvas.json`; тело артборда из `.dc.html` кладётся в `parts/`.

Экраны (`home/`, `sidebar/`, `auth/`) держат разметку внутри своих `build.mjs` и тянут из кита
`STYLE` и нужные `parts/<Имя>.css` — кит для них источник, не наоборот.
