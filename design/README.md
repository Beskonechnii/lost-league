# design/ — макеты LOST

## Принцип: атомы в одном месте, экраны — отдельно

- **Атомы (кнопки, поля, переключатели, бейджи, свитчер темы, …) → один кит** `kit/`
  («Кит элементов»). Это единый источник элементов и рецептов (STYLE). Новый элемент
  заводится **здесь**, а не в отдельном ките — иначе плодятся дубли.
- **Экраны и секции (сайдбар, будущие страницы) → свой канвас**, но на рецептах кита:
  их `build.mjs` переиспользует `STYLE` из `kit/build.mjs` (см. `sidebar/build.mjs`).
  Так «одно место» соблюдается на уровне элементов и STYLE, а кит не распухает
  композициями. Композиция берёт готовый атом из кита, а не рисует свой.


Канонический макет — **`kit/`** («Кит элементов», Light Clay). Артефакт-превью:
https://claude.ai/code/artifact/de74082f-62a9-46ca-b381-b12a204ab6d1

## Что где

- `kit/build.mjs` — **источник истины**: вся разметка артбордов + общий CSS (pouf-рецепты).
- `kit/*.dc.html` — вывод генератора, 7 артбордов. Регенерируются: `node build.mjs`.
- `kit/canvas.json` — раскладка артбордов на канвасе + аннотации.
- Собранный `lost-clay-kit.html` (~2.6MB) — вывод сборки канваса, в git **не** коммитим.

## Цикл правки

1. Правим `kit/build.mjs` (не `.dc.html` — их перезапишет генератор).
2. `cd design/kit && node build.mjs` — обновит `.dc.html`.
3. Скилл `design` пересобирает канвас из `.dc.html` + `canvas.json`.
4. Публикуем **по тому же URL** артефакта (`Artifact url=…`), новый не плодим.
