Ты выполняешь **один** этап большой задачи репозитория LOST (League of Spirit) — в своём контексте,
чтобы не раздувать основной чат. Рабочая папка проекта — `lost-league`, код живёт в `web/`.

## Порядок

1. **Прочитай план и журнал.** План активной задачи — файл, названный в задании (по умолчанию
   `ACCOUNTS-PLAN.md`); журнал — верхняя запись `WORKLOG.md`. Карта проекта — `CLAUDE.md`,
   жёсткие правила папки — `web/AGENTS.md`.
2. **Определи этап.** Если номер задан — бери его. Если нет — первый незакрытый по плану.
   **Делай ровно один этап**, даже если следующий кажется мелким: границы этапов выбраны осознанно.
3. **Сделай работу** по разделу плана. План — источник правды: решения в нём уже приняты,
   не переигрывай их.
4. **Проверь.** Из `web/`: `npx tsc --noEmit` и `npm run lint`. Замечания, существовавшие до тебя
   (в файлах, которых ты не касался), не чини — просто не считай своими.
   UI-изменения проверяй в браузере, а не «на глаз»: дев-сервер поднимай конфигурацией
   `web-dev-4203` (порт 3000 часто занят сервером пользователя из другого окна).
   Правил схему БД — не забудь `npx prisma generate`, иначе типы разъедутся.
5. **Запиши результат.** Новая запись сверху в `WORKLOG.md` по формату файла (дата, что сделано,
   файлы, что дальше) и отметка о выполнении этапа в самом плане (строка статуса вверху).
6. **Отчитайся** коротко: что сделано, какие файлы тронуты, чем проверено, что осталось.

## Правила

- **Не коммить и не пушить.** Коммит делает отдельный агент `ship` после тебя.
- **Упёрся в развилку, которой нет в плане** (нужен выбор пользователя, план противоречит коду,
  задача больше, чем описано) — **остановись и верни вопрос** как результат. Не выдумывай решение
  и не расширяй объём молча.
- Комментарии и UI — по-русски. Комментарий объясняет **почему**, а не пересказывает код.
- Prisma 7: клиента не создавать (`src/lib/prisma.ts` — singleton), импорт `@/generated/prisma/client`,
  sqlite не умеет enum → строковые поля с комментарием-перечислением.
- Next.js 16 новее того, что ты «помнишь»: непривычный API — читай `web/node_modules/next/dist/docs/`,
  а не полагайся на память.
- `.env` не трогать и ключи никуда не печатать.
- Данные пользователя не портить: если для проверки нужны записи в БД — заводи временные и убирай
  за собой, а результат проверки честно опиши (в том числе если что-то не сошлось).
- Ничего не выдумывать в отчёте: не прошло проверку — так и напиши.
