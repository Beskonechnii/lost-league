# sheet — лист контрольных кадров

Dev-сервер поднимает человек (скрипт его не трогает: два dev-сервера в одной папке Next 16 не
разрешает). Проверь, что он жив, и снимай:

```
curl -s http://localhost:3000/api/health          # пусто/ошибка → cd web && npm run dev
cd web && npx tsx scripts/screen-sheet.ts         # весь лист
cd web && npx tsx scripts/screen-sheet.ts --only=home,admin   # подмножество
```

Последняя строка stdout — путь к листу (`web/.sheets/screen-sheet.png`, перезаписывается,
в `.gitignore`). Покажи его Стасу и жди список замечаний **по всему листу разом**: смысл
процесса — закрыть вёрстку одним заходом, а не двадцатью кругами «правка → сборка → превью»
(`CLAUDE.md`, `docs/PROCESS-REVIEW.md` §4).

## Что знать

- Список экранов — `web/scripts/screen-sheet.screens.ts`. Новый экран = строка в конфиге:
  `name` (ключ для `--only`), `path`, `widths`, `auth` для экранов за входом. Логику не трогаем.
- Адреса с id и слагами в конфиге конкретные (`/players/bsk`, `/overlay/draft/42`). Данные
  локальной базы поменялись — правится строка конфига, иначе кадр уйдёт в пропуск с HTTP 404.
- Экраны за входом снимаются сессией `DEV_LOGIN_EMAIL` (`web/.env`). Переменная пуста — такие
  экраны пропускаются строкой в stdout, форма входа за готовый кадр не выдаётся. Переменную видит
  **dev-сервер**, поэтому после правки `.env` его надо перезапустить.
- Ширины: 390 / 1280 / 1440 продуктовым экранам, 1920×1080 эфирным сценам. Длинный кадр режется
  по 4000 точкам — в подписи тогда «обрезан по высоте».
- Сбой одного экрана прогон не рвёт: причина печатается строкой и попадает в врезку на самом листе.
- Снимается только локальный dev (`localhost`, не `127.0.0.1`). Боевой сайт проверяет `qa`
  по `docs/SMOKE.md`.
