# pickup — подхватить работу с другого устройства

Первое, что делает новая сессия: синхронизируется с git и восстанавливает контекст из
`WORKLOG.md`, а не из памяти чата. Обратная сторона — скилл `handoff`.

## Шаги

### 1. Синхронизация

```bash
git fetch origin --prune
git status -sb
git log --oneline -3
```

Разбери, что видишь:

- **Ветка отстаёт от origin** → `git pull` (в облачной сессии — просто, у неё свежий клон;
  на компе сначала убедись, что нет своих незакоммиченных правок).
- **Есть незакоммиченное** → покажи Стасу и спроси, что с этим делать, прежде чем что-то менять.
  Особенно если тронут `web/prisma/dev.db`: бинарник не мержится, потерять данные легко.
- **Существует непримёрженная ветка `claude/*`** → скажи о ней и о её PR, если он есть:
  это работа прошлой сессии, которую могли забыть влить.

### 2. Контекст

Прочитай **верхнюю запись** `WORKLOG.md` — что сделано в прошлый раз, какие файлы трогали,
что помечено как «Дальше». Загляни в `BACKLOG.md`, если предстоит выбирать задачу.
Структуру проекта не пересказывай по памяти — она в `MAP.md`.

### 3. Короткая сводка

Ответь Стасу без воды: ветка и её состояние относительно `main`, где остановились в прошлый
раз, что напрашивается следующим шагом. Дальше — жди задачу, сам в код не лезь.

## Правила

- Не начинай работу, пока не разобрался с расхождением веток — иначе правки лягут не туда.
- В облачной сессии `web/prisma/dev.db` не трогаем (см. `handoff`): база — забота компа.
- Если непонятно, на каком устройстве что осталось, — лучше спроси, чем угадывай.
