# stage — один этап по плану, затем коммит

Большая задача разбита на этапы в плане (`TOURNAMENTS-PLAN.md`). Этап выполняет сабагент `stage`
в **своём** контексте, а сюда возвращается короткий отчёт — так основной чат не раздувается
полными транскриптами работы.

## Что делать

1. Вызови сабагента и дождись его:

   ```
   Agent(subagent_type: "stage", run_in_background: false,
         description: "Этап <N>",
         prompt: "Выполни этап <N> из TOURNAMENTS-PLAN.md.")
   ```

   Номер этапа не назван пользователем — так и передай: «следующий незакрытый этап».
   Если в сессии всплыло решение, которого нет в плане, добавь его в `prompt` одной фразой.

2. **Прочитай его отчёт.** Дальше две развилки:
   - агент **вернул вопрос** (упёрся в развилку) — покажи вопрос пользователю и **не коммить**;
   - агент **сделал этап** — перескажи отчёт своими словами (что сделано, чем проверено)
     и переходи к шагу 3.

3. Закоммить сделанное скиллом `ship` — то есть сабагентом `ship`, как обычно.

4. Одной строкой скажи, что дальше: какой этап следующий по плану.

## Что помнить самому

- **Один вызов = один этап.** Не запускай следующий, не показав пользователю результат текущего:
  между этапами он может передумать.
- Сабагент **не может спросить пользователя посреди работы** — он вернётся с вопросом.
  Поэтому чем подробнее план, тем меньше остановок; решения фиксируй в плане, а не в чате.
- Отчёт сабагента пользователю не показывается — пересказывай сам, включая то, что **не** получилось.
- **Модель этапа — Opus 5, `effort: high`** (задано в `.claude/agents/stage.md`). Это осознанное
  исключение из «по умолчанию Sonnet»: этапы трогают доступ, права и миграции — цена ошибки выше
  экономии. Дешёвая работа (коммит) остаётся на `ship`, он на haiku.
  Разово понизить: `Agent(..., model: "sonnet")`.
- Проверки (`tsc`, `lint`, браузер) — обязанность сабагента; если в отчёте их нет, спроси его
  через `SendMessage`, а не считай, что всё хорошо.
