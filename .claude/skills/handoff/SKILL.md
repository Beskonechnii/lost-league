# handoff — закрыть сессию под продолжение на другом устройстве

Работа идёт то с телефона (облачная сессия), то с компа. Контейнер облачной сессии живёт
недолго и после неё исчезает: **всё, что не в git, теряется.** Этот скилл закрывает сессию так,
чтобы на другой стороне хватило одного `git pull` и чтения `WORKLOG.md`.

Обратная сторона — скилл `pickup`.

## Шаги

### 1. Проверь базу (только в облачной сессии)

Облачная сессия **не коммитит `web/prisma/dev.db`**: бинарник не мержится, а на компе база
почти всегда новее — сетка встреч и результаты вводятся руками в UI.

```bash
[ -n "$CLAUDE_CODE_CONTAINER_ID" ] && echo "облако" || echo "локально"
git status --short web/prisma/dev.db
```

Если ты в облаке и база изменилась — **не коммить её**: `git checkout -- web/prisma/dev.db`,
а в отчёте скажи, что именно её меняло. Если изменения в базе были осмысленной частью работы —
останови передачу и спроси Стаса: варианта два, выгрузить снимок (`npm run db:export`,
`data/snapshot.json` — текст, мержится) или повторить действие на компе.

Схема — другое дело: `prisma/schema.prisma` и `prisma/migrations/` коммитятся всегда.

### 2. Запись в WORKLOG

Допиши **сверху** (новейшее первым), по формату файла: дата, заголовок этапа, «Сделано»,
«Файлы», «Дальше». Формат подсмотри в верхней записи — `sed -n '1,60p' WORKLOG.md`, не в файле целиком.
Пиши так, чтобы следующая сессия поняла состояние без этого чата:
что сделано, что проверено, где остановился и почему.

Если этап не закончен — так и напиши: «не доделано: …». Честная запись полезнее красивой.

### 3. Коммит и пуш

Через скилл `ship` (он зовёт сабагента, тот сам читает дифф и формулирует сабж).
Ветку не переключай — пушится текущая.

### 4. Памятка Стасу

Заверши коротким блоком — без него передача не считается сделанной:

- команды для той стороны:
  `git pull` (работа лежит в `main`);
- одной строкой — на чём остановились и что делать первым.

## Правила

- **Работаем прямо в `main`** — единственная ветка репозитория, пуш в неё штатный.
  Другая сторона забирает работу через `git pull`, а не через PR.
- Не оставляй незакоммиченного: дерево в конце чистое, `git status` пустой.
- Файл-мусор (патчи, дампы, скриншоты), созданный по ходу, — удали до коммита.
- Ничего не выдумывай в WORKLOG: не проверял в браузере — так и пиши.
